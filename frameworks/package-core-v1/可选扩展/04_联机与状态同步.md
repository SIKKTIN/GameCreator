# 可选扩展：联机与状态同步

[返回目录](../README.md)

## 1. 启用边界

只有项目需要多人联网或远程权威执行时使用。本扩展不属于单机基础规范。

联网结构不一定都是相同的客户端 / 独立服务器模式。项目先确定主机、服务器、对等端或平台托管方式，再明确各项规则由谁执行。

## 2. 保留 Package 边界

```text
本地输入
  → 网络请求入口
  → 验证身份与操作权限
  → 权威执行处调用业务公开接口
  → 返回结果与必要状态
  → 界面更新
```

网络入口负责把外部请求转换成可信上下文；业务包负责玩法规则。不要只在客户端检查条件，也不要相信请求正文中自报的身份和权限。

单机可以直接调用同样的业务接口，但不要求单机增加网络传输或伪造服务器角色。

## 3. 三种通道分开

| 通道 | 用途 |
| --- | --- |
| 本地函数调用 | 同一运行环境内查询和命令 |
| 本地事件 | 已发生事实的进程内通知 |
| 网络消息与复制 | 跨端请求、结果和状态传播 |

不把所有本地事件自动广播到网络。每类消息应明确发送者、接收者、数据结构、可见性和兼容版本。

## 4. 命令与状态

- 哪些状态由谁最终决定，需要明确。
- 客户端请求表示意图，不能直接写入任意字段。
- 权限与输入验证覆盖目标对象、数量、频率和当前业务条件。
- 可能重复的命令使用适合该业务的去重方式；不能全靠客户端不重复点击。
- 明确乱序、超时和断线时的状态。超时不一定表示远端没有执行。
- 玩家私有数据、公开数据和仅服务器可见数据分别处理。

## 5. 按需能力

预测、回滚、重连、主机迁移、跨服和反作弊是独立需求，不因为“支持联机”就默认已具备。

采用引擎现成复制机制时仍需验证其对象寿命、可见性和更新规则。框架不统一底层网络 API。

## 6. 验收

启用的能力至少覆盖正常请求、无权限、非法输入、重复请求、对象失效，以及项目支持范围内的断线恢复。

未支持的情况写入项目限制，不在文档或界面中暗示已完成。
