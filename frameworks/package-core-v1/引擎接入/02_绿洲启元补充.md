# 绿洲启元补充

[返回目录](../README.md)

## 1. 适用范围与证据

本节仅适用于沿用原 PackageGuider 约定的绿洲启元 / Lua 项目。说明依据原六份文档，没有在本次工作中核查运行时代码或测试具体行为。

原资料目录：`PackageGuider/`。

这些约定不是其他引擎或单机项目必须采用的基础规范。

## 2. 可以保留

- Registry 作为 Lua Package 对外入口，内部模块使用 local / require。
- Query、System、Data 的职责拆分，按复杂度决定是否创建目录。
- Core 负责通用机制，Package 负责业务含义。
- Config 经领域规则校验，生成 Setting 与业务配置分开。
- GenKit、PackageKit、AutoTestKit 已有接入方式，在明确其能力范围的前提下使用。

## 3. 仅在当前接入中需要

| 约定 | 所属范围 |
| --- | --- |
| PlayerController / GameState 挂载数据 | 引擎数据宿主 |
| Lua 字段与蓝图属性保持一致 | 引擎对象绑定 |
| GetReplicatedProperties 中登记字段 | 当前网络复制接入 |
| 服务端修改、客户端查询或表现 | 当前执行权限与同步模式 |
| UGC 平台存档 API | 平台保存实现 |
| BeginPlay / Tick 注册索引 | 当前生命周期与工具接入 |

通用规范不要求复制这些名称或关系。已有项目有上述依赖时，也不能只删除服务端判断或复制字段就认为完成了通用化。

## 4. Meta 和数据入口

现有 Package_Meta 包含 dependsOn、playerData、gameData 等内容，并使用 Lua 函数引用绑定 DataInit / DataFormat。

- 对原项目，可以继续使用符合现有工具的格式。
- 对新单机项目，Meta 和数据登记可不启用。
- 希望跨语言生成时，再设计可静态解析声明及目标语言绑定。
- DataFormat 按原文档是调试打印，不是存档迁移函数。
- 读取声明及其依赖时应避免顶层业务副作用，不能因为 Meta 自己只返回表就默认所有 require 都无副作用。

## 5. DataCore 现状需要牢记

原文档说明：QueryPackage 可能返回实际可变表；批量修改不提供通用事务；保存失败不自动回滚；旧存档恢复后不自动运行默认初始化；没有统一数据版本迁移回调。

因此不得在新说明中声称这些保证已经存在。需要只读边界、全有或全无、旧档补字段时，在公开接口或后续扩展中明确实现并验证。

原保存链路中的枪械、护甲快照和历史任务数据清理属于项目业务或兼容需求。迁移时由对应业务或项目迁移层承担，先保留数据键和旧档行为，再逐步调整调用位置。

## 6. 关于“不要增加引擎中间层”

原 Package_Structure 用这条规则避免无意义的等价转发。新的通用规范保留这个目的，同时允许因多环境、测试隔离或统一生命周期而产生的真实适配边界。

不能据此要求每个引擎调用都加一层，也不能据此禁止所有必要适配。

## 7. 工具验证边界

原文档明确 PackageKit 不等于完整循环依赖与架构方向分析，GenKit 生成成功也不等于业务正确。AutoTestKit 的单 Case 清理和 setup / teardown 异常行为应按实际实现评估。

继续使用原工具时，在项目 README 写清已覆盖的检查与人工补充，不把新规范中的目标能力当成原工具已有实现。
