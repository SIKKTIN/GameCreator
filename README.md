# GameCreator

GameCreator 是一个面向游戏内容和数据配置的本地客户端。当前包含项目切换、项目概览、玩法核心、玩法设计、功能系统、美术资产、故事文档、数据配置、Lua 枚举扫描、稳定版本审核，以及本地直达／团队账号登录。

## 启动

```powershell
npm install
npm run dev       # 浏览器开发模式
npm run desktop   # Electron 本地客户端
```

本机多人协作验证：运行 `npm run collaboration:demo`，打开 Alice 和 Bob 两个客户端。本地和团队项目共用左上角项目列表及故事编辑页，支持完整故事导入、共享编辑、冲突提示、本机草稿和修改历史。普通客户端可从项目列表选择“连接团队服务器”。详见 [多人协作验证](docs/collaboration.md)。

启动页提供“本地工作区”和“团队协作”两个入口。本地工作区直接进入，不再区分 admin/user；团队协作填写服务器地址和团队账号密码，单项目直接进入，多项目选择后进入，无项目时提示联系管理员。记住上次入口、地址与账号，不保存密码或登录令牌。

桌面客户端可从启动页“管理本机服务器”或工作区左侧“本机服务器”启动、查看和停止自己托管的本机服务。关闭客户端或退出团队账号后服务继续后台运行，重新打开客户端仍可管理；外部启动的服务仅可连接。当前仅支持本机连接，需要 Node.js 24.11 或更新的兼容版本。

同一台服务器可保存多个协作项目。管理员从项目列表选择“新建协作项目”，使用团队 admin 连接后填写名称、配置成员权限，即可进入空白项目。项目管理员可在“成员管理”中调整权限，各成员只看到自己加入的项目。当前共享项目概览、玩法核心和故事文档，支持基本信息、独立里程碑、真实动态和成员列表。编辑者默认“概览只读、故事和玩法核心可编辑”，项目管理员可按项目单独授权或收回模块编辑权；只读成员只能查看。

团队服务器管理员登录后，左侧“管理”分组显示 **用户与权限** 模块，可创建账号、启用／停用、重置密码、设置服务器角色，并配置自己管理的项目权限。团队连接使用账号密码输入。账号停用或密码重置会使旧会话失效，历史内容和本机草稿保留；系统保护最后一位有效管理员。用户与模块权限管理要求服务接口版本 6，升级后需重新连接团队。

选中本地项目后，管理员也可从项目列表选择“发布为协作项目”，预览并一次发布项目概览、里程碑、玩法核心和全部故事文档、设置协作名称和成员。原本地项目保留，其他模块留在本地；发布结果会被记录，重试或重启客户端后可进入已有协作项目，不覆盖团队修改。单次最多 500 篇故事、200 个里程碑、10 MiB。旧发布项目在团队概览尚未编辑时可从原发布入口一次性“补充项目概览”。玩法核心要求服务接口版本 7，升级后重启服务并重新连接。旧发布项目也可在玩法核心尚未编辑时一次性“补充玩法核心”。节点位置各自在本机保存，拖动不产生团队版本；内容按流程图检查冲突并提交。

Alice 等团队账号应在“团队协作”入口登录；管理员重置密码后使用新密码。初始演示账号及服务器数据位置见 [协作说明](docs/collaboration.md)。

## 项目切换

点击左上角项目名称，可切换已有项目。可使用“新建项目”，只填写名称即可创建并切换到空白项目（初始不带配置表），先编写介绍、故事和配置数据。需要连接游戏工程时，再到“引擎设置”填写工程目录与枚举目录并点击“保存设置”。各项目的内容和引擎设置独立保存，后续修改目录不会更换项目存档，重启恢复上次选择。

详细操作见 [项目切换与独立存档](docs/project-switching.md)。还可从项目菜单导出完整的普通文件夹，再从文件夹导入为独立项目，连同美术原始文件和版本历史一起迁移。见 [项目文件夹导出与迁移](docs/project-package.md)。

窗口左上角的侧栏按钮可以隐藏或显示主导航栏。隐藏后编辑区使用释放的宽度，当前页面、画布视图和编辑内容保留。本机记住显隐偏好，切换项目及重启后沿用；此偏好不随项目导出。

可在项目列表中右键点击本地项目，确认后从列表删除。项目存档和外部文件保留；删除最后一个项目后可在空工作区重新创建或导入。

## 玩法核心

在左侧“玩法核心”用图形整理游戏入口、模式分支和玩法循环。节点可拖动，连线记录操作与流转条件；双击循环模块进入内部流程，通过目录或面包屑返回上层。节点可引用已有玩法设计，支持持续经营等无终点循环。内容按项目保存，并随项目文件夹及 AI 文档导出。四个原型示例包含可展开的循环图，已有项目不会被示例更新覆盖。详见 [玩法核心](docs/gameplay-core.md)。

## 玩法设计

在左侧“玩法设计”创建玩法，逐步填写体验目标、核心循环、规则、原型范围和试玩验证。支持玩法依赖图、全部/任一条件规则、状态流程与手动路径预览，以及可编辑空间布局、事件时间轴与空间联动预览；也可复制、归档、关联故事和配置表，并独立自动保存，无需先连接引擎。详见 [玩法设计](docs/gameplay-design.md)。

## 调试 MCP

项目提供一个无需额外依赖的 stdio MCP 调试服务：

```powershell
npm run mcp:debug
```

在 MCP 客户端配置：

```json
{
  "mcpServers": {
    "gamecreator-debug": {
      "command": "node",
      "args": ["E:/Project/GameCreator/mcp/debug-server.mjs"]
    }
  }
}
```

可用工具：

- `inspect_path`：检查工程目录、枚举目录和 Lua 文件数量。
- `scan_const_directory`：解析 Lua 枚举，返回组数、成员数、排序数组和动态 ID 提示。

## 美术资产

管理美术需求、玩法与功能来源、交付文件、版本审核与当前采用素材。创建只需名称，占位素材可先用于原型验证，正式交付需通过审核。详见 [美术资产](docs/art-assets.md)。

## 任务与流程

在“任务与流程”编辑玩家目标、阶段、条件分支与成功／失败结果，关联玩法、功能、故事、素材和配置，使用手动路径预览检查推进路线。五个原型包含13个任务示例，支持本地自动保存、AI文档和项目文件夹迁移。详见 [任务与流程](docs/task-flows.md)。

## 原型示例

需要编写分支对白和完整故事链时，可在 **工作区设置 → 添加故事编排** 按项目启用。支持章节场景、正文与选项、角色状态、条件后果、检定、故事结构和独立试玩；关闭保留内容。极乐迪斯科原型包含港区疑案故事，已有项目可从现有对白配置导入。详见 [故事编排](docs/story-orchestration.md)。

故事编排中的“人物”提供卡片、可拖动关系图和跨故事人物库；“叙事发言者”按需管理旁白、内心声音或系统播报；“故事状态”独立分类维护事实与数值。检定可选数值比较或自定义骰子规则，可用于不同题材的叙事游戏。

[五套完整设计快照](examples/prototypes/README.md)保存空洞骑士、星露谷、植物大战僵尸、极乐迪斯科和吸血鬼幸存者原型的玩法、功能系统、美术需求、资产台账及引用数据。可从左上角项目列表选择“从原型示例创建项目”，只填写名称即可复制为独立本地项目；已有项目不会被覆盖，重复创建也互相独立。操作与保存规则见 [原型示例](docs/prototype-examples.md)。示例独立于本机存档，可以使用 `node scripts/validate-prototype-examples.mjs` 校验。

管理员在“用户与权限 → 协作项目管理”可删除服务器中的协作项目（服务接口版本 8）。先核对项目标识和文档/流程数量，再输入完整项目名称确认；确认期间有新保存时需重新核对。删除清理团队内容与成员配置，原本地项目和客户端未提交草稿保留。删除后的本地来源可明确确认后重新发布为一个新的协作项目。


团队项目的 **项目排期** 已接入协作（服务接口版本 10）。任务、日期、依赖及验收记录按任务／里程碑保存并检查冲突，编辑者默认只读，可由项目管理员单独授权。概览里的里程碑使用同一份数据；本地项目发布时携带完整排期。升级服务后重新连接即可使用，详见 [排期协作](docs/project-schedule.md#团队协作)。
