# 项目规范

入口位于“项目概览”下方，是本地项目的基础模块。内置 23 条规则，涵盖通用更新原则与 15 个内容领域，适用于不同游戏类型和引擎。

## 规则与项目补充

- **通用规则**：先复用再扩展，按职责组织内容，保持当前有效规则一致，保留稳定 ID、引用及开发成果，说明兼容方案，分开记录需求、实现与验收。
- **模块组织**：玩法核心按玩家循环、玩法设计按体验主题、功能系统按职责组织；版本号不默认成为业务分类或父级流程。排期仍可按版本组织交付。
- **更新检查**：展示“查阅现状 → 兼容方案 → 影响核对 → 按归属修改 → 检查验收 → 同步上下文”六步。只读检查玩法分类、核心流程、功能关联和排期依赖；重复 ID、失效引用提示结构问题，相似名称、版本容器提示复核。

检查不是全项目的语义验证，不自动移动、合并或删除条目；缺少来源或来源保存失败时明确提示检查不完整。是否存在重复实现、是否应新建系统，仍由管理者结合需求判断。

内置规则统一维护，每个项目可以填写通用补充和各模块补充。补充内容自动保存，失败时保留草稿并阻止导出，可重试或下载草稿后重新读取。补充与通用规则冲突时，应明确处理依据；不会把补充文本当代码执行。

## 老项目与保存

项目规范使用独立 `project-standards` 存档：`{schema:1, notes, moduleNotes}`。旧项目未保存该存档时读取空补充、展示内置规则，不改写玩法、系统、分类、排期或示例内容。完整项目导入导出包含规范补充；缺少此存档的旧项目包仍可读取。

普通 `project_write` 反馈不能修改规范自身，避免开发者通过修改约束来批准自己的变更。规范由管理者在 GameCreator 界面维护。团队服务器的此模块尚未接入共享，沿用其他未接入模块的禁用提示。

## AI 文档与工程协作

- 生成 AI 文档时，总文档和单独的“项目规范.md”均包含通用规则与本项目补充。
- 同步设计文档时，项目规范固定包含在 `modules/project-guide/standards.md`，即使旧同步配置没有勾选此模块。
- 开启开发协作时，即便关闭设计文档同步，也会输出 `gamecreator/project-standards.md`。协作 README 和开发者说明将它列为更新前必读，比较快照包含此次交付的规范。
- 规范及项目补充支持全局搜索；搜索结果定位到相应模块规则。

基于新快照的 `spec_change`、`project_change` 反馈需要填写兼容方案：

```json
{
  "compatibility": {
    "reuse": "复用哪些已有内容，保留哪些身份和规则",
    "modify": "修改哪些条目与字段，分别归属哪里，如何兼容",
    "add": "确需新增什么，为什么不能直接复用；没有写无",
    "archive": "哪些内容不再有效，如何处理引用和历史；没有写无"
  }
}
```

四项必须完整且非空，签名包含这些内容。管理者在差异页核对方案、原因与影响后应用，处理记录保留方案。该说明不授予新增/删除操作能力；项目修改仍受现有字段、权限与验收限制。普通进度反馈不要求填写，未包含项目规范的历史快照仍兼容旧格式。新快照的完整模板随工程同步到 `gamecreator/project-changes.md`。
