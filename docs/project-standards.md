# 项目规范

“项目管理 → 项目规范”维护当前项目约定。“使用帮助 → 通用规范”集中展示固定的 23 条内置规则，涵盖通用更新原则与 15 个内容领域；无需打开项目即可阅读。

## 规则与项目补充

- **项目整体约定**：当前项目的术语、坐标系、数据来源、实现范围等，沿用原来的 `notes` 字段。
- **模块约定**：玩法、素材、配置、程序框架等模块的具体要求，沿用 `moduleNotes`。
- **更新检查**：只读检查玩法分类、核心流程、功能关联和排期依赖；重复 ID、失效引用提示结构问题，相似名称、版本容器提示复核。

检查不是全项目的语义验证，不自动移动、合并或删除条目；缺少来源或来源保存失败时明确提示检查不完整。是否存在重复实现、是否应新建系统，仍由管理者结合需求判断。

内置规则统一维护，每个项目可以填写通用补充和各模块补充。补充内容自动保存，失败时保留草稿并阻止导出，可重试或下载草稿后重新读取。补充与通用规则冲突时，应明确处理依据；不会把补充文本当代码执行。

## 老项目与保存

项目规范使用独立 `project-standards` 存档：`{schema:1, notes, moduleNotes}`。旧项目未保存该存档时读取空约定，不改写玩法、系统、分类、排期或示例内容。界面拆分直接沿用已有补充，无需重填。完整项目导入导出包含规范补充；缺少此存档的旧项目包仍可读取。

普通 `project_write` 反馈不能修改规范自身，避免开发者通过修改约束来批准自己的变更。规范由管理者在 GameCreator 界面维护。团队服务器的此模块尚未接入共享，沿用其他未接入模块的禁用提示。

## AI 文档与工程协作

- 生成 AI 文档时，总文档和单独的“项目规范.md”均包含通用规则与本项目补充。
- GameCreator 项目根目录的 `PROJECT_STANDARDS.md` 包含完整内置规则与项目自定义约定，随新建项目、更新协作文件、初始化刷新；现有非受管同名文件不会被覆盖。
- 引擎的 `modules/project-management/standards.md` 只包含本项目自定义约定，固定随文档或开发协作同步生成，未填写时明确显示暂无。协作 README 和成员说明链接到同一文件。
- 通用规则和使用说明保留在管理项目；旧引擎副本经预览和明确选择才移除。当前项目的自定义约定支持全局搜索，内置规则在使用帮助中查阅。

基于新快照的 `spec_change`、`project_change` 反馈需要填写兼容方案：

```json
{
  "compatibility": {
    "reuse": "复用哪些已有内容，保留哪些身份和规则",
    "modify": "修改哪些条目与字段，分别归属哪里，如何兼容",
    "add": "确需新增什么，为什么不能直接复用；没有写无",
    "archive": "哪些内容不再有效，如何处理引用和历史；没有写无"
  }
}
```

四项必须完整且非空，签名包含这些内容。管理者在差异页核对方案、原因与影响后应用，处理记录保留方案。该说明不授予新增/删除操作能力；项目修改仍受现有字段、权限与验收限制。普通进度反馈不要求填写，未包含项目规范的历史快照仍兼容旧格式。新快照的完整模板随工程同步到 `gamecreator/project-changes.md`。
