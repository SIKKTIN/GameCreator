# 功能系统

功能系统用于整理面向程序的实现职责，与玩法设计共同描述项目。

## 系统、功能和玩法

一个系统定义职责与边界，包含多个功能。每个功能只归属一个系统，但可以被多份玩法使用。新建系统或功能只要求名称，其他信息可逐步补全。

例如，玩家能力系统提供玩家冲刺，移动教学使用它，试炼解锁它，裂隙关卡要求它。首领冲刺斩击属于敌人技能系统，由敌人 AI 发起；两者共同调用移动、角色状态与战斗能力。系统目录表达职责归属，不强制对应一个代码类或完全独立的执行框架。

功能说明记录用途、输入、条件、处理流程、输出、异常/打断、关键状态和验收要点。实现状态为待开发、开发中、待验收、已完成，由使用者维护，与玩法的设计状态、制作清单和实机试玩结果独立。

## 目录展开与收起

每个系统左侧箭头独立展开或收起所属功能，系统名称仍用于打开职责说明。顶部可以全部展开或全部收起。收起正在编辑的功能后，右侧内容保留，所属系统标记当前选择。

搜索或筛选实现状态时自动展开匹配项，清除筛选后恢复原折叠状态。进入功能、从玩法引用跳转或移动功能归属时展开所属系统；切回模块时确保当前功能可见。

折叠偏好保存在本机 `gamecreator.workspace.v1:<项目标识>:functional-view`，按项目隔离，不进入项目导出或功能内容存档。保存偏好失败不阻止编辑，并提示本次窗口仍可使用。

## 双向引用与需求来源

在玩法“设计说明”的“实现功能”区域选择已有功能；也可以从功能的“关联玩法”页签选择玩法并填写使用场景。两边操作同一份关系存档，反向列表实时计算。

引用可指向整个玩法，或其中一条条件规则、一个状态、一个时间事件。跳转打开对应玩法及来源。标题变化通过 ID 解析，来源失效或归档会显示提示。

玩法原有“系统关系”页签改称“玩法关联”，继续保存玩法之间的依赖、包含和协作；程序功能间的依赖在功能系统模块中管理。

## 依赖与配置

依赖分为调用功能、读取数据、订阅事件，箭头由使用者指向提供者。关系说明写明需要对方提供什么。查看系统时聚合功能依赖；查看功能时聚焦直接上下游，并支持按关系类型筛选。

界面分别列出依赖对象、使用者和关联玩法，检查自身引用、重复/失效关系及调用循环。事件反馈与调用循环分开处理。

配置引用保存表、可选记录及字段的 ID，并实时展示当前数据。修改配置后，功能中显示的值和 AI 文档一起变化；数据删除或字段变化不会静默丢弃引用，而是提示修复。

## 归档、保存和导出

归档系统及功能保留内容与引用，并停止编辑；可以恢复后继续修改。系统含有功能时无法删除，功能被玩法或其它功能引用时也无法直接删除。移动功能到其它系统保持功能 ID。所属系统已失效的功能会集中显示，可重新指定系统；来源功能已失效的入向依赖也可解除，避免无从修复。

存档键为 `gamecreator.workspace.v1:<项目标识>:functional-systems`，使用独立 schema 1，统一包含系统、功能、依赖和玩法引用。缺少存档的旧项目显示空目录。只查看不会创建或改写存档，玩法 schema 3 不因新增模块升级。

自动保存延续本地原子写入、备份和过期写入检查。保存失败保留草稿并显示重试入口，切换项目或测试工作区以及导出受到保护；关闭窗口时提示未保存修改。损坏存档停止写入。

AI 文档增加功能系统章节，完整定义每项功能一次，包含职责、输入输出、依赖、实时配置和玩法来源。玩法章节列出所用功能，便于从体验需求追踪到程序模块。

## 验证

构建：`npm run build`。

模型：`node --test tests/functional-systems.test.mjs`。

桌面：`node tests/desktop-functional-systems.cjs`（需要可用的 Playwright；可用 `GAMECREATOR_PLAYWRIGHT_PATH` 指定模块路径）。桌面测试使用隔离存档和用户配置，不编辑真实项目。

## 空洞骑士示例职责

示例包含 9 个系统、17 项功能。玩家能力系统包含冲刺、骨钉攻击与聚焦治疗；敌人技能系统包含首领冲刺斩击及跃砸；敌人 AI 系统负责原有敌人决策与重置。战斗系统专注命中与伤害结算。原功能 ID、执行细节、依赖、玩法和美术引用保持不变。

维护工具 `scripts/reorganize-hollow-knight-systems.mjs` 提供显式整理函数。它仅处理仍保持原职责与归属的示例，保留自定义执行内容；已修改职责或归档的系统不自动覆盖。打开项目不会触发模板迁移。
