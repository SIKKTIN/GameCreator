# 枚举版本审核与稳定发布

## 使用流程

1. 在引擎设置中配置项目目录和枚举目录。
2. 打开枚举管理，点击“扫描更新”。首次连接会自动建立候选快照。
3. 检查新增、删除、改值、注释和排序的差异；展开每项可查看绑定字段和受影响记录。
4. 勾选要导入的变更。新增默认选中，高风险删除和改值默认不选。
5. 高风险项需要逐项确认，并填写审核说明。删除已使用的成员还需要选择替换目标或保留为待修复值。
6. 检查发布预览，然后点击“批准所选变更并发布稳定版本”。

扫描和审核不会更新数据下拉框。只有发布成功才会切换稳定版本。首次稳定版本也需要明确发布。

## 选择性更新

- 未选中的修改保留稳定版本中的原定义，下次扫描仍会显示差异。
- 新增枚举组按整组选择；已有枚举的成员新增、删除、改值、注释与排序可以分别选择。
- 成员重命名以删除旧成员和新增成员呈现，不自动猜测重命名。批准新增目标后，将旧成员显式映射到目标。
- 删除整个枚举组时，如果仍有字段绑定，则禁止发布该删除。可以先保留该组、发布其他更新，再调整字段绑定。
- 动态生成的定义仍只作提示，不进入稳定版本。

## 发布与迁移

发布前检查审核基准、选择项、确认项、说明、成员重复、重复值、混合类型与迁移目标。
若确认保留已删除成员的旧值，记录会保留并标记为待修复，导出检查不通过。
预先存在的数据问题会在预览中列出，不阻止与其无关的枚举发布，但仍阻止数据导出。
数据记录保存成员键；实际数字或字符串值始终由当前稳定快照解析。

稳定版本、审核结果、迁移记录和数据草稿使用同一次本地存档写入提交。写入失败时不会切换内存中的稳定版本。
同一工程通过浏览器 Web Locks 串行写入，并检查存档修订号。旧页面排队的编辑不能覆盖已迁移或已修改的数据。

## 回退

版本记录可回退到上一次切换前的稳定版本，同时反向恢复该次发布迁移的成员键。
发布后对这些迁移单元格的修改会导致冲突，禁止自动覆盖；无关字段的后续修改会保留。
若回退使当前有效绑定或成员失效，会阻止回退。已有的无效值继续保留并阻止导出。
回退本身也写入版本记录。回退期间仍在审核的候选如果基准失效，需要重新扫描。

## 本地存档

- 按规范化后的工程路径隔离保存。
- 源快照和发布快照都保留创建时间、唯一 ID、SHA-256 摘要与完整枚举内容。
- 审核选择、确认项、说明、迁移映射、发布历史，以及数据配置中的字段和记录均可在刷新后恢复。
- 相同候选内容的再次扫描会保留原审核选择；不同候选会归档旧审核，创建新的待审核记录。
- 审核人为本地手动填写的记录信息；目前没有多人账号或远程审核服务。
- 当前存储是同一浏览器、同一站点地址下的 localStorage，不是工程磁盘文件。清除网站数据、更换浏览器或更换端口不会共享这份存档。

## 导出保护

数据配置页面展示全工程导出检查。候选版本不参与数据解析或导出。
getExportSnapshot 只提供稳定版本及当前数据；没有稳定版本或存在字段、枚举、引用问题时拒绝返回导出数据。
Lua 文件生成仍待后续接入，当前没有写回 Withdraw 源文件。

## 实现位置与验证

- src/enum-versions.ts：快照、差异、选择性合并、影响分析、迁移、回退、导出检查。
- src/enum-storage.ts：存档读取与原子写入、修订冲突检查。
- src/useEnumRegistry.ts：工程级版本状态、扫描请求、浏览器锁和持久化。
- src/EnumReviewPanel.tsx：审核、迁移、发布和历史界面。
- tests/enum-versions.test.mjs：版本发布与迁移回归测试。

运行：node --test tests/enum-bindings.test.mjs tests/enum-versions.test.mjs

浏览器验收使用 tests/fixtures/enum-review：首次发布 A=1、B=2；扫描 A=11、C=3 后验证旧下拉框不变；仅批准 C 和 B→C，验证 A 仍为 1；刷新恢复审核；回退恢复 B；错误目录扫描仍可使用稳定版本。测试后恢复 Withdraw 路径及测试 Lua 初始内容。
