# 岗位工作与 AI 协作令牌

入口仍位于“项目排期”下方的“人员分配”，包括“岗位总览”“岗位任务”“协作令牌”。

## 使用方式

1. 在岗位总览查看制作人、策划、程序、美术、测试、音效的职责和工作清单。这里统一显示岗位，不预建程序A、程序B等执行者。
2. 点击岗位修改职责、勾选该岗位负责的排期任务。可添加自定义岗位，一项工作也可以归入多个岗位。
3. 进入协作令牌，填写实际执行的 AI 名称，也可复用已有执行者。
4. 多选工作岗位，再多选具体任务，填写本轮分配名称和工作说明，选择反馈权限与有效期。
5. 点击“生成并领取凭证”，把私有凭证单独保存并交给相应 AI。签发成功后才创建执行者与工作分配；保存失败不会留下半份分配。
6. 在引擎设置开启开发协作并同步。工程会收到岗位、任务、执行分配和本次工作的独立说明。AI 完成工作后提交签名反馈，在 GameCreator 核对和应用。

例如给“战斗开发助手”勾选程序、美术，再选择“实现同路战斗”“接入单位动画”。另一名 AI 可以在同一程序岗位领取不同的工具任务；岗位卡片仍只有一张“程序”。

## 岗位与任务

默认按排期的制作方向归类：设计、关卡归入策划；程序归入程序；美术归入美术；测试归入测试。“其他”不会被猜测为音效。制作人和音效的具体工作由用户选择。

尚未自定义归属的任务跟随制作方向。手动调整后，任务保留明确的岗位列表，优先于默认规则。更改职责、名字、任务归属不会修改完成状态、实际日期或验收结果。

岗位任务使用依赖关系从左向右展示，支持岗位、状态和里程碑筛选、右键拖动画布、滚轮缩放。跨岗位任务在总览线路只显示一次，在各岗位筛选内都能查看。

执行工作以令牌中明确选中的任务为准。新增任务不会自动加入旧令牌，切换岗位时会清除不属于剩余岗位的待选任务；搜索只是筛选，不清空已有选择。“选择当前结果”只选择当前可见任务。

项目排期的任务列表、时间轴和进度线路显示当前令牌执行者，原有负责人字段保留。任务详情可以调整岗位并查看令牌分配；执行者命名和工作分配在协作令牌中完成。

## 权限与变更

| 权限 / intent | 用途 |
| --- | --- |
| 制作进度 / `progress` | 提交工作状态、实际日期、制作结果、工具开发情况 |
| 验收结论 / `review` | 提交完成结论和交付验证结果 |
| 排期与分配建议 / `propose` | 提交任务拆分、分工、排期建议，保存为独立建议记录 |

岗位不自动授予验收权限。新执行者在签发时明确选择权限；复用执行者时不能超出其已有权限。一个执行者可有多份令牌，各自只包含选中的工作。重复领取同一工作会提示已有执行者，允许协作；每份令牌的工作范围独立。

新令牌仅接受当前仍属于所选启用岗位的已选任务。岗位停用、任务移出岗位、执行者停用、权限收回、令牌过期或撤销后，相关反馈会停止接收。工具通过明确引用该工具的已选任务判断范围。读取、单条应用、批量应用和最终写入前都会核验。

普通执行反馈应提交“待验收”，不能直接提交“已完成”“可使用”“停用”。验收反馈仍须在界面核实完成情况；里程碑继续由管理者确认。建议反馈只追加记录，不覆盖实际日期、分配和开发结果。

调整已签发的工作范围时，撤销旧令牌，为同一执行者重新勾选工作并签发。关闭领取窗口后不再显示私钥。公共存档只包含验证信息，私有凭证不放入共享工程和版本库。令牌用于验证反馈，不控制 AI 在外部开发环境的文件访问。

## 工程输出

```text
gamecreator/
├─ project.json
├─ context/
│  ├─ team.json                    岗位、执行者与公开令牌信息
│  ├─ assignments.json             任务归属及令牌分配
│  ├─ tasks.json                   工作规格、依赖与进度
│  ├─ tools.json
│  └─ snapshots/                   已交付的比较基准
├─ assignments/<令牌ID>.md          本次工作说明、具体任务、交付要求
├─ members/<执行者ID>.md            执行者的分配说明和历史任务
├─ submit-feedback.cjs             签名反馈工具
├─ feedback/                       AI 提交的反馈
└─ receipts/                       处理回执
```

AI 文档的完整文件与“人员分配”模块文件均包含岗位及工作分配；私钥不会写入这些文档。普通同步不会重新签发令牌。

从工程根目录执行：

```text
node gamecreator/submit-feedback.cjs "私有目录/战斗开发助手.json" "反馈草稿.json" gamecreator/feedback
```

需要 Node.js。草稿从 `project.json` 复制真实 `projectId`、`engine`、`snapshotId`，从工作清单复制任务 ID。例如：

```json
{
  "schema": 1,
  "projectId": "实际项目ID",
  "engine": "godot-gdscript",
  "snapshotId": "实际快照ID",
  "target": { "kind": "task", "id": "已分配任务ID" },
  "intent": "progress",
  "summary": "完成战斗功能，提交验证",
  "evidence": ["交付文件", "运行入口与测试结果"],
  "changes": { "status": "待验收", "result": "实现内容、测试结果与剩余问题" }
}
```

工具补齐作者、更新编号和签名，完整写入后发布，不覆盖已有反馈。私钥不会出现在反馈中。每项反馈使用新编号，冲突仍需人工选择。

## 旧数据兼容

旧版成员、任务负责人、任务分配、凭证和处理记录保留。打开页面即按岗位展示，不把重命名后的“程序”“程序B”视作两个岗位，也不猜测并覆盖旧成员职责。原成员在“协作令牌 → 执行者记录”中可查看或停用，并可在签发时复用。

旧凭证继续遵循旧的成员任务范围；新签发的工作令牌遵循明确选择的岗位和任务。旧凭证保留到过期或撤销，不会被新界面自动扩权。未签名反馈在存在执行者时需逐条确认来源，不能一键应用，无效签名不能跳过验证。

项目存档 schema 1 新增可选 `personnel.positions`、`task.positionIds`，工作令牌保存 `positionIds`、`taskIds` 与 `workDescription`。保留旧 `members` 和 `task.assignment`。项目复制会保留岗位和分配记录，但凭证绑定原项目 ID，副本需重新签发。

本模块面向本地项目与外部 AI 工具协作；与团队服务器的登录账号分别管理。
