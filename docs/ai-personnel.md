# AI 人员分配

入口位于侧栏“项目排期”下方，包含成员总览、任务分配、协作令牌三个页签。每个成员代表一个在外部开发环境工作的 AI 助手；通过工作说明、私有协作凭证和工程反馈协作，与团队服务器的登录账号分别管理。

## 开始使用

1. 打开“人员分配”，点击“创建默认 AI 团队”：制作人、策划A、程序A、美术A、测试A、音效A。也可单独添加成员；同类名称自动递增为程序B、程序C等。
2. 点击成员卡片填写职责、勾选多个岗位，设置允许提交的反馈和任务范围。成员可以兼任多个岗位；同岗位也可以有多个成员。
3. 在“任务分配”点击任务设置主负责人、协作者和验收负责人。可先预览建议分配，勾选后应用；现有负责人文字只做唯一姓名完全匹配，空负责人按唯一岗位候选建议，存在歧义时保留待分配。“其他”任务不自动推断为音效。
4. 在“协作令牌”选择成员、反馈权限、有效期及可选的任务限制，点击“生成并领取凭证”。单独保存或复制凭证给该 AI；关闭领取窗口后，私钥不再可查看。需要更换时先撤销旧令牌再签发新令牌。
5. 保存工程连接，在“引擎设置 → 同步配置”开启开发协作，预览并同步。把成员工作说明与对应私有凭证交给 AI，再在“开发反馈”查看和应用交付结果。

创建团队不会重写原任务、负责人、日期或完成情况，也不会自动分配任务。成员改名保留稳定 ID，并一次更新已绑定任务的负责人显示。停用成员保留任务和历史，立即停止接受其新反馈；重新启用恢复未到期、未撤销的令牌。已撤销令牌始终不能恢复使用。

## 分配与可视化

任务与项目排期共用一个存档。排期任务详情和人员分配都能编辑分配关系，主负责人至多一名、协作者可多名、验收负责人至多一名。岗位描述职责，权限独立配置，勾选“测试”岗位不会自动得到验收权限。

成员卡片统计其负责、协作或验收的任务，每项任务只计一次。任务线路按主负责人分行、按前置依赖从左向右排列，支持成员、状态、里程碑筛选，右键拖动和滚轮缩放。成员筛选包括该成员协作、验收的任务，它们仍位于实际主负责人的行，避免误解归属。没有负责人或引用失效的任务保留显示供修复。

## 反馈权限

| 权限 / intent | 可以提交 | 范围 |
| --- | --- | --- |
| 制作进度 / `progress` | 工作状态、实际日期、制作结果；工具开发情况 | 主负责人或协作者的任务，或明确授权项目范围 |
| 验收结论 / `review` | 状态与验收结果；工具交付结论 | 指定的验收任务，或明确授权项目范围 |
| 排期与分配建议 / `propose` | 任务 `result` 中的建议文本 | 已分配任务，或明确授权项目范围 |

执行反馈不能直接提交“已完成”“可使用”“停用”，应提交待验收。验收反馈不能改实际工作日期。接收完成状态仍须在 GameCreator 勾选核实验收；里程碑仍由用户确认。

`propose` 应用后追加到任务的“AI 排期与分配建议”，不覆盖任务结果、状态、日期或分配；用户查看建议后在相应界面调整。这样制作人可以提出任务拆分或重新分配，而不把建议误当成已经执行的变更。

令牌权限与成员当前权限取交集。令牌可额外限定任务，但不能超出成员当前任务范围；工具反馈通过引用该工具的任务核验范围。任务改分配、成员停用、权限收回、令牌过期或撤销，在读取及应用反馈时都会重新检查，包括批量应用和写入前的最后检查。

## 工程协作文件

```text
gamecreator/
├─ project.json
├─ context/
│  ├─ team.json                 成员、岗位、职责及公开令牌信息
│  ├─ assignments.json          任务 ID 与分配关系
│  ├─ tasks.json                任务规格、依赖及当前进度
│  ├─ tools.json
│  └─ snapshots/                已同步的比较基准
├─ members/<成员ID>.md           每个启用成员的工作说明
├─ submit-feedback.cjs          Node.js 签名提交辅助工具
├─ feedback/                    AI 提交的签名反馈
└─ receipts/                    GameCreator 处理回执
```

AI 文档导出另包含独立的“人员分配”模块 Markdown，完整文档也包含同一内容。新模块不复制任务数据为第二套排期。

私有凭证文件不属于上述共享目录。GameCreator 使用 Ed25519 密钥签名，项目存档只保存公开验证信息；公共文档和同步目录不包含私钥。同步不会重新签发令牌。令牌控制反馈接收，不隔离本地文件访问；拿到工程文件的工具仍受其运行环境的文件权限约束。

## AI 提交示例

准备反馈草稿，从 `project.json` 和 `context/tasks.json` 获取真实项目、快照和任务 ID：

```json
{
  "schema": 1,
  "projectId": "复制实际项目ID",
  "engine": "godot-gdscript",
  "snapshotId": "复制当前快照ID",
  "target": { "kind": "task", "id": "复制任务ID" },
  "intent": "progress",
  "summary": "完成种植功能，提交验证",
  "evidence": ["相关文件位置", "运行入口与测试结果"],
  "changes": { "status": "待验收", "result": "已实现内容、验证结果与剩余问题" }
}
```

从引擎工程根目录运行（路径含空格时加引号）：

```text
node gamecreator/submit-feedback.cjs "私有目录/程序A.json" "反馈草稿.json" gamecreator/feedback
```

工具自动补齐作者、更新编号和签名，完整文件写好后才发布到反馈目录，并拒绝覆盖已有反馈。每次反馈使用新编号；不把私钥写入反馈。该工具与引擎无关，运行需要 Node.js。

GameCreator 验证后显示绑定的 AI 名称、反馈类型及字段差异；作者文字不能替代凭证。冲突仍须选择保留当前值或采用反馈，历史更新不会重复应用。

## 兼容与存储

人员配置保存在 `project-schedule.personnel`，任务分配保存在 `task.assignment`；现有 schema 1 使用可选字段扩展。旧项目没有人员字段时正常打开。旧版反馈在启用团队后保留读取能力，但需逐条确认来源，不参与一键应用；带有无效签名的反馈不能作为旧版反馈跳过验证。

复制、另存为或导入项目时，成员、任务分配及公开令牌记录保留；凭证绑定原项目 ID，独立副本必须重新签发。私钥不会跟随项目包复制。成员使用记录从任务与工具的反馈历史读取，撤销不会删除旧记录。

人员编辑和任务分配沿用排期的保存重试与并发检查。签发凭证前核对当前项目及排期快照，写入失败不返回可领取凭证。领取窗口阻止尚未保存凭证时直接切换项目；遗失凭证可撤销重发。
