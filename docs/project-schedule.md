# 项目排期

项目排期管理开发制作计划，入口位于“项目概览”下方。游戏中玩家的任务、阶段、分支与解锁继续在“任务与流程”设计。本模块目前用于本地项目，尚未接入团队共享。

## 制作任务

任务独立记录名称、说明、制作方向（设计、程序、美术、关卡、测试、其他）、负责人、优先级、计划起止日期、实际起止日期、所属里程碑、验收条件与验收结果。负责人可直接填写，不要求事先配置团队服务器。

制作状态为待开始、进行中、待验收、已完成或受阻，由制作人员明确设置。修改状态不会自动填写实际日期，也不会改动关联文档、程序功能或美术的状态。设计说明完成、实现完成、素材交付与试玩验证通过应分别记录。

任务可关联多个玩法文档、程序功能、美术需求、美术资产、地图或原型场景。详情显示来源的当前状态，并可直接打开。来源删除、归档或地图模块关闭时保留引用与提示；可以修复或移除关联，不会丢失任务。

## 时间轴与列表

默认以时间轴显示任务，可按里程碑、制作方向或负责人分组，各组可以收起。任务列表便于比较日期、状态和优先级。搜索覆盖名称、说明、制作方向与负责人，可结合状态筛选。

时间轴按日计算，起止日期均包含在任务时长中。拖动时间条整体移动；拖动两端调整开始或结束日期；调整到负时长时保持原日期。方向键移动一天，两端手柄的方向键调整相应日期。Esc 或指针取消会放弃本次拖动。只有结束拖动时才保存日期，实际日期和其他任务不会跟随更改。

视窗可选择 6、12 或 24 周，支持前后翻页、指定起始日期、定位今天或首项。超出当前时段的任务保留入口；未填写完整起止日期的任务显示“待排期”。时间轴内部滚动，任务名称固定在左侧。

## 依赖与验收

一个任务可以有多个前置制作任务，全部前置完成后才能开始。日级排期中，开始日期应晚于前置任务的结束日期；同日仍视为重叠。界面提示前置未完成、循环依赖、日期重叠、延期、无效引用和里程碑超期等情况。它们作为可修复的计划问题保存，不自动改期、完成或阻止保存草案。

里程碑记录阶段目标、负责人、目标日期、验收条件和验收记录。卡片展示所属任务完成比例；里程碑的“已验收”单独确认，不由任务比例自动推断。已验收但仍有未完成任务、缺少验收记录等情况会提示。

删除任务会移除其他任务对它的前置依赖，设计来源保留。删除里程碑后任务移入未分组，不删除任务。两种删除均需在界面确认。

## 概览与旧项目

项目概览与排期共用同一份里程碑。点击概览中的里程碑会打开排期详情，“添加里程碑”也进入该模块。概览完成度继续按里程碑验收比例计算，排期任务完成度另行展示。

旧项目尚无排期存档时，从旧概览里程碑读取标题、负责人、日期和状态，使用稳定标识；非标准日期留在说明中，日期字段置空待补充。读取不自动写盘。首次修改时保存完整排期，原旧存档保留，并检查旧里程碑是否被其他窗口修改。已有排期存档后以排期为准，不会反复导入旧里程碑。概览发布也使用当前排期中的里程碑字段。

## 保存与迁移

每个项目使用独立的 `gamecreator.workspace.v1:<项目ID>:project-schedule` 存档，schema 1，包含 tasks 与 milestones。新项目、测试工作区和不同项目相互隔离；内置原型不会虚构负责人、日期或已完成的制作计划。

修改自动保存；磁盘写入失败时保留当前草稿，阻止退出登录或切换项目，并提供重试、导出草稿和重新读取。损坏存档停止写入，恢复文件后可以重新读取。并发写入比较已保存原文，避免覆盖其他窗口的修改。

项目文件夹包含可选的 `data/project-schedule.json`，纳入快照检查和校验和保护。旧包缺少该部分时从包内旧里程碑恢复；实际日期、依赖、来源与验收记录完整迁移。AI 文档包含制作任务、里程碑、计划与实际日期、依赖、来源和待处理提示。完整排期仍留在本地项目包，不会通过概览发布自动共享制作任务。

开发校验：`node --test tests/project-schedule.test.mjs`；桌面交互：`node tests/desktop-project-schedule.cjs`。桌面包校验从模型生成：`node scripts/sync-project-schedule-validator.mjs`。
