# 本机多人协作验证

本地项目和团队项目共用客户端入口、左侧项目切换器和故事编辑页。故事支持完整的标题、分类、状态、摘要、正文、标签、大纲以及角色／地点／系统关联。团队项目通过服务端保存，提供项目成员权限、分文档版本检查、更新同步、冲突对照、修改历史和本机草稿。

团队项目开放项目概览和故事文档，其他业务模块在左侧明确标注“未接入”并禁用。本地项目的所有原有模块继续按原方式保存。可以发布本地项目的概览、里程碑和故事，也可单独导入故事，原本地存档保留。

## 启动

需要 Node.js 24.11 或更新的兼容版本。服务端使用 Node 内置的 SQLite；此版本 Node 会输出实验性 SQLite 提示。

### 管理员在客户端启动

使用本机管理员账号 `admin / admin123` 登录桌面客户端，从左侧“管理”分组进入独立的“服务器管理”页面，再点击“启动服务器”。页面显示运行状态、连接地址、数据目录和启动时间，可复制地址或停止服务。无论当前选择本地还是团队项目，都可进入此模块管理同一台本机服务，不受团队模块“未接入”限制。

“连接团队服务器”窗口中的“前往服务器管理”会跳转到此模块；“返回连接设置”保留已填写的成员、密码和地址，点击“使用此地址连接”则填入本机服务地址并返回连接窗口。从编辑页进入时，点击“返回工作区”或左侧故事模块可回到原文档，保留当前选择和草稿。进入管理页时若原工作区正在保存或草稿落盘失败，会保留原页面以便完成保存或重试。

通过客户端启动的服务是独立的后台进程：关闭客户端或退出登录后，其他客户端仍可连接；再次打开同一工作区的客户端并以管理员登录，即可查看和停止原服务。停止前需要确认，已保存的数据和历史保留。电脑关机时服务会停止，当前不提供开机自动启动。默认仅监听 `127.0.0.1:4747`，连接范围仍是本机。

模块权限取决于右上角的本机登录账号：`admin` 显示并可进入，`user` 隐藏；团队成员身份与此分开。例如本机 admin 连接为 Bob 时仍可管理，本机 user 连接为团队 admin 时仍无管理权限。页面和桌面主进程都执行权限检查，不能通过修改浏览器存储中的角色启用服务器控制。退出管理员登录后清除管理页面状态。桌面登录在本次客户端进程内有效，重新打开需要登录；浏览器页面不能启动或停止本机进程。

如果端口上已经有通过命令行或演示脚本启动的协作服务，界面显示“外部服务运行中”，可以直接连接，但不能从这里停止。要改由客户端管理，需要先在原启动位置停止服务。其他程序占用端口时会显示错误，不会终止占用程序。

后台进程需要可用的 Node.js。默认使用系统 PATH 中的 `node`，也可在打开客户端前设置 `GAMECREATOR_NODE_PATH` 为 Node 可执行文件的绝对路径。

### 双客户端演示

```powershell
npm ci
npm run collaboration:demo
```

此命令先构建界面，随后启动仅监听 `127.0.0.1:4747` 的服务，再打开 Alice 和 Bob 两个 Electron 客户端。先使用现有本机账号登录（默认 admin / admin123），演示窗口会自动弹出“连接团队服务器”，分别确认 Alice、Bob 后点击“连接并进入项目”。两个窗口都关闭后，演示服务自动停止。服务端数据库会保留，再次启动可继续使用。

也可以分别启动服务和正常客户端：

```powershell
npm run build
npm run collaboration
# 在另一个终端
npm run desktop
```

普通客户端从左上角项目列表选择“连接团队服务器”，连接后同一列表中会显示“本地项目”和“团队项目”。切换项目时使用对应的数据源；未接入的团队模块不会回退到本地保存。团队页面显示服务器地址、当前团队成员、权限和连接状态。“连接设置”可切换团队账号，“断开团队连接”返回本地项目。

浏览器也可打开 `http://127.0.0.1:4747/?team=alice` 和 `http://127.0.0.1:4747/?team=bob`。团队账号会话仅保存在各页面内存中，不在标签页间共享；刷新或服务重启后需要重新连接。服务器和项目列表会记录在本机，断开时列表仍可查看，点击未连接的团队项目会要求登录。

旧版演示服务升级后需要重启服务和客户端。数据库启动时自动补充故事扩展字段、导入来源表、服务器角色、成员配置版本、项目创建、本地项目发布记录，以及概览、里程碑、动态表，保留既有名称、成员、文档、版本号与历史快照。旧项目概览的新增字段为空，不填入演示内容；旧草稿会补充缺失字段继续恢复。旧数据库中的演示 admin 获得服务器管理员身份。项目与成员管理要求接口版本 3；项目概览及完整本地项目发布要求版本 5。版本 4 客户端的故事发布接口仍兼容，新客户端会提示旧服务升级。重启服务后需重新连接以获取新会话。

固定演示账号：

| 账号 | 密码 | 初始演示项目权限 |
| --- | --- | --- |
| admin | admin123 | 管理员 |
| alice | alice123 | 编辑者 |
| bob | bob123 | 编辑者 |
| viewer | viewer123 | 只读成员 |

这是本机流程验证服务；账号初始化只在首次创建数据库时执行，当前可配置这四个账号的项目成员身份，尚不提供用户注册或创建账号。新建项目的成员由创建者选择，各项目可以设置不同权限。接口逐次校验会话和项目权限，密码在服务端以随机盐和 scrypt 派生值保存。正式联网部署前应更换演示账号流程，增加部署配置、HTTPS 与备份方案。

## 新建多个协作项目

1. 使用本机 admin 登录，在“服务器管理”启动服务。已有运行中的同一服务可以复用，不需要为每个项目另开进程、IP 或端口。
2. 左上角项目列表 → **新建协作项目**。尚未连接服务器管理员会话时，先填写服务地址，使用团队 `admin / admin123` 连接。
3. 输入项目名称，为现有账号选择“不加入此项目／管理员／编辑者／只读成员”。创建者保留项目管理员权限。
4. 点击“创建并进入协作项目”。新项目没有示例故事，可新建文档或使用“从本地导入故事”；本地项目不会自动转为协作项目。
5. 其他客户端连接同一个地址后，只显示该团队账号已加入的项目。已连接客户端约每 3 秒更新项目列表和成员信息，约每 2 秒更新当前文档及权限。

项目在同一个 `team.sqlite` 中按独立项目 ID 存储，名称相同的项目也不会串数据。创建请求重试会复用已成功创建的项目；修改创建内容则视为新请求。

三个权限范围各自生效：本机 admin 控制本机后台进程和创建入口；服务器 admin 可以创建协作项目；项目管理员可以编辑该项目文档及配置成员。授予 Alice 某项目的管理员权限，不会授予她创建服务器项目或管理本机进程的权限。

项目管理员从团队页顶部的 **成员管理** 或概览里的 **管理项目成员** 调整项目权限。当前操作账号必须保留管理员身份，避免误删自己的管理权限。管理员和编辑者可修改概览、里程碑和故事，只读成员只能查看。两个管理员同时修改成员配置时，过期提交会提示重新读取，避免覆盖彼此配置。

移除成员或调整权限后，服务端立即按新配置校验已有会话。客户端下一次刷新会更新可见项目和编辑权限；被移除成员的当前编辑页显示访问已撤销，本机未提交草稿仍保留。重新加入同一项目后可以恢复草稿。

## 数据位置

- 团队共享数据：`.gamecreator/collaboration/team.sqlite`，包括用户、项目、成员、概览、里程碑、动态、文档及故事每次成功保存的历史快照。
- 客户端管理的服务日志：同一协作数据目录中的 `host.log`。`.host-runtime.json` 保存后台服务的管理凭据，供重新打开的客户端识别并控制原服务；正常停止后删除，勿提交或分享此文件。管理凭据不会交给界面或团队成员。
- SQLite 运行时可能有 `team.sqlite-wal`、`team.sqlite-shm` 文件。备份时先停止服务再复制整个数据目录，不能只复制正在使用的主数据库文件。
- 默认客户端的未提交草稿：通过已有磁盘存储保存到 `.gamecreator/storage/`，存储键前缀为 `gamecreator.team-draft.v1:`，按服务实例、成员、项目及文档／基本信息／单个里程碑隔离。
- 团队连接信息：`gamecreator.team-connection.v1`，仅保存地址、服务器标识、上次成员名及项目目录，不保存密码或令牌。
- 本机导入来源标识：`gamecreator.local-source.v1`，用于重复导入识别。
- 双客户端演示各自的数据：`.gamecreator/team-clients/alice/` 和 `.gamecreator/team-clients/bob/`，包括 Electron 用户目录及本机草稿。
- 浏览器验证的草稿保存在该浏览器来源的 localStorage；更换服务端口将更换浏览器草稿来源。

可用 `GAMECREATOR_TEAM_DATA_DIR` 指定仓库外的持久化数据目录。独立服务和客户端管理入口都支持 `GAMECREATOR_TEAM_PORT` 修改端口，需在启动对应程序前设置；其他客户端需填写对应地址。客户端管理入口的默认团队数据目录始终是仓库下的 `.gamecreator/collaboration`，与个人客户端的 `GAMECREATOR_DATA_DIR` 分开。双客户端演示固定使用 4747。所有默认数据目录均被 Git 忽略。

## 协作规则

1. 输入内容即时保存为本机草稿；点击“保存到团队”并收到服务端确认后，才显示共享保存成功。
2. 每两秒检查更新。没有本机修改时自动显示最新内容；存在本机修改时保留草稿并显示冲突面板。
3. 每篇文档单独维护版本号。不同文档可分别提交；同一文档的过期版本提交返回 409，不覆盖已提交内容。版本检查、内容更新和历史快照在同一个数据库事务中完成。
4. 冲突时右侧展示团队最新的标题、分类、摘要及正文。编辑左侧草稿后，点击“已合并，准备提交”，再保存到团队。如果其他人在此期间再次提交，会再次提示冲突。
5. “采用最新版本并丢弃草稿”会明确放弃当前未提交编辑，采用已保存的团队版本。首版不自动合并文字，也不锁住整篇文档。
6. 断线后可继续编辑本机草稿，保存到团队会报告失败。服务恢复后可重试；服务重启会使会话失效，需要退出并重新登录同一账号，草稿仍可恢复。
7. 修改历史可查看最近 50 次成功提交的完整快照。首版只提供查看，不提供回滚按钮。

## 将本地项目发布为协作项目

本机 admin 选中正式本地项目，在左上角项目列表点击 **发布为协作项目**。尚未以服务器管理员连接时会先打开连接窗口，连接后继续发布预览；取消连接会取消本次发布流程。普通本机 user、测试工作区和已进入的团队项目不提供此入口。

预览显示来源项目、目标服务器、概览与里程碑、全部故事数量，可展开查看内容，修改协作项目名称并设置成员。点击 **发布并进入协作项目** 后，创建独立的协作副本并切换到故事文档页，再从左侧进入项目概览。没有故事的本地项目也可发布。

发布项目基本信息、里程碑和全部故事文档，包括标题、分类、状态、摘要、正文、标签、大纲及角色／地点／系统关联文字；概览名称以发布窗口指定的协作名称为准。玩法核心、玩法设计、数据配置、美术等内容不上传，协作副本中仍标注“未接入”并禁用；原本地项目的内容及模块完整保留。发布后本地与团队独立编辑，不自动双向同步。团队文档及里程碑获得新的 ID，以发布账号记录版本 1；故事另存初始历史。

单次最多 500 篇故事、200 个里程碑，整个 JSON 请求不超过 10 MiB，故事数量和请求体限制定义在 `shared/publication-limits.json`。客户端和服务器都会检查大小、数量及字段，超过限制或本地存档损坏时停止发布，不截断内容。预览之后本地概览、里程碑或故事内容发生变化，会要求重新读取预览；已经配置的协作名称和成员保留。

项目、成员、概览、里程碑、动态、故事、初始历史、导入来源与发布记录在一个数据库事务中保存，失败时全部回滚。服务器按“本机来源标识 + 本地项目 ID”记录一次发布，在同一台服务器重复点击、网络超时后重试、客户端或服务重启后操作，均复用已有协作项目，不覆盖其内容或成员配置。再次打开发布入口时会显示 **进入已发布项目**。服务器不可达时不会把未知结果当作尚未发布。

发布记录保存在服务器的 `project_publications` 表，客户端沿用 `gamecreator.local-source.v1` 的本机来源标识，无需保存密码或发布令牌。该来源标识应与本地数据一起保留；换成新的本机存档或导入为新的本地项目，会被视为不同来源。查询已有发布结果同样检查服务器管理员身份和目标项目成员权限。

发布后如需补充新的本地故事，可以在协作项目使用“从本地导入故事”。已发布过的原文档会被识别并跳过，团队后续修改不会被重新导入覆盖。

旧版仅发布故事的项目，在原本地项目的发布入口提供 **补充项目概览**。服务器管理员且仍为该项目管理员的账号可以预览并一次性补充基本信息和里程碑，保留团队当前名称、成员、故事和历史。只有尚未初始化的团队概览允许补充；任何成员保存过概览或里程碑后，这个入口不再可用。服务器在同一事务内检查，防止另一成员同时编辑时被覆盖。补充成功但响应丢失时，重试会提示进入已有项目。

## 项目概览协作

从团队项目左侧进入 **项目概览**，编辑名称、类型、目标平台、版本、状态与简介，点击 **保存基本信息到团队**。保存名称后项目列表也会更新。关键里程碑支持添加与编辑标题、负责人、日期和状态；负责人为自由文本，日期可填写计划日期或说明。每个项目最多 200 个里程碑，完成率根据已完成数量计算。

基本信息整体维护一个版本，每个里程碑各自维护一个版本。两人编辑不同里程碑可分别保存；同一内容出现冲突时保留本机草稿，展示团队最新字段，手动合并后重新提交。草稿可在概览、故事、服务器管理之间切换后继续，也可在重启客户端并重新连接相同账号后恢复。新里程碑尚未填写标题时也能恢复草稿；未提交的新里程碑可明确丢弃。

成员区域展示实际项目成员与权限，不显示虚构在线状态。最近动态显示升级后真实发生的基本信息、里程碑、成员与故事操作，最多显示最近 50 条；它不是概览的历史快照或回滚功能。已有故事历史继续独立保留。

## 从本地项目导入故事

在团队项目中点击“从本地导入故事”，选择来源本地项目，并查看待复制的文档。可以展开预览，检查正文、状态、标签、大纲及关联设定，然后勾选需要的文档并点击“复制 N 篇到团队”。每批最多 50 篇，总请求上限 5 MB；较大项目可以分批导入。

复制在服务端一个事务内完成，任意文档校验失败时整批不写入。重复导入同一本机、同一本地项目、同一来源文档会跳过已有副本，不覆盖团队成员后续修改；请求超时后重试也不会重复创建。不同来源项目内相同名称或相同文档 ID 的故事分别处理。团队副本获得独立 ID，导入行为进入修改历史。原有角色、地点、系统关联为文字设定，按原内容保留。

只读成员无法导入，接口也执行同样的权限校验。损坏的本地存档会提示错误并停止导入，不会改写为演示内容。原本地项目、故事和其他模块存档不会被导入流程修改。

## 验收

- Alice 编辑“世界背景”，Bob 编辑“第一章剧情”，两边分别保存成功，并在另一个客户端看到更新。
- 两人都修改“世界背景”，Alice 先保存；Bob 收到冲突，自己的正文仍保留，可对照、合并并重新提交。
- 使用 viewer 登录，界面只读；直接调用写入接口同样会返回 403。
- 断网或停止服务后编辑，刷新或重启并重新登录，恢复同一账号的本机草稿。
- 重启服务，已提交内容和修改历史仍存在。
- 从同一项目列表切换本地／团队，团队草稿可以恢复，本地故事仍保持原样。
- 导入完整本地故事，在另一客户端核对所有字段；重复导入跳过已复制内容。
- 团队项目中的玩法、配置、美术等模块处于禁用状态，本地项目仍可使用。
- 管理员启动服务、保存团队内容后关闭客户端，另一客户端仍可读取；重新打开后可停止并重启服务，数据保留。
- 普通本机账号不能管理服务；外部协作服务可连接，但不能被客户端停止。
- 两个管理员客户端中的服务器状态随启动或停止更新；从本地／团队编辑页往返管理模块后，当前文档与草稿仍保留。
- 同一服务新建两个空白协作项目，给 Bob 和 Alice 分配不同项目；两人的项目列表与故事内容互不混用。
- 将 Bob 改为只读、移除、重新加入项目，验证权限及时生效且未提交草稿仍可恢复。
- 发布含 60 篇故事的本地项目，核对完整字段及初始历史，验证其他模块仍留在本地且协作侧禁用。
- 模拟发布提交成功但响应丢失，重启客户端后进入同一个协作项目，确认期间团队成员的修改和原本地数据都保留。
- 两个客户端修改基本信息与不同里程碑，检查名称、完成率及动态同步；同一内容的修改触发冲突。
- 概览断线草稿、新里程碑草稿在切换模块和重启客户端后恢复；成员降权或移除后停止编辑和访问。
- 本地发布包含概览与里程碑；旧发布项目可补充一次，团队已编辑后不能用本地概览覆盖。
