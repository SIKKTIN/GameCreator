# 从原型示例创建项目

管理员登录后，打开左上角项目列表，选择 **从原型示例创建项目**。选择空洞骑士、星露谷物语、植物大战僵尸、极乐迪斯科或吸血鬼幸存者，填写项目名称，点击 **创建并打开**。名称可自行修改，无需先设置引擎目录。

每次创建都会生成一个新的本地项目，完整复制示例中的玩法核心、玩法设计、原型设计、功能系统、美术需求与资产台账、配置表和故事文档。五套示例随软件一起提供，桌面客户端离线也可创建；不需要先访问 GitHub 或手动复制本机存档。

## 内容与保存

- 示例是可继续编辑的设计基线，不包含可运行的游戏、美术交付文件或引擎枚举稳定版本。美术需求尚待制作，资产没有交付版本、采用记录或素材文件；制作和试玩检查项仍待完成。
- 每份示例只提供实际使用的配置表：空洞骑士 8 张、星露谷物语 9 张、植物大战僵尸 4 张、极乐迪斯科 15 张、吸血鬼幸存者 16 张，不附带通用空表。普通新项目从零张配置表开始，可按需新建。
- 原型内部的稳定 ID 保留，使玩法规则、空间对象、时间事件、程序功能、美术需求与配置记录之间的关系可以正常定位。项目本身使用新的独立 ID，因此重复创建同一示例也互不覆盖。
- 创建后，编辑内容和新增交付文件保存在自己的本地项目中，重启软件会恢复。修改副本不会改动仓库中的示例 JSON，也不会影响之前创建的副本。
- 创建过程完成后才加入项目列表并切换。若存档写入失败，旧项目保持选中，弹窗保留名称和示例选项，修复问题后可以重试。
- 此入口只创建软件内置的五套示例。任意 JSON 文件导入、已有项目覆盖、示例升级合并不在本功能范围内。

## 与 Git 和团队项目的关系

Git 保存软件代码及 [示例设计快照](../examples/prototypes/README.md)。拉取或切换代码分支不会自动新增、覆盖或同步本机项目；需要在客户端明确选择创建示例项目。

从团队项目的项目列表打开此入口，创建的仍是独立的 **本地项目**。它不会把玩法、配置或美术模块上传到团队服务器。当前团队工作区的故事协作范围见 [多人协作验证](collaboration.md)。

不要将整个 `.gamecreator` 目录加入 Git。需要更新共享示例时，只更新 `examples/prototypes` 中对应的设计文件，保留它引用的模块和配置，并运行校验。

## 验证

只读校验示例内容和跨模块引用：

```powershell
node scripts/validate-prototype-examples.mjs
```

构建后可执行桌面验收（需要可用的 Playwright）：

```powershell
npm run build
node tests/desktop-prototype-import.cjs
```

若 Playwright 不在项目依赖中，可通过 `GAMECREATOR_PLAYWRIGHT_PATH` 指定其模块目录。测试自行创建临时客户端档案与存储，验证五套示例完整导入、模块显示、重复创建隔离、修改后重启恢复、中途写入失败与重试、最终项目列表写入失败，以及已有项目和示例文件保持不变。测试截图与统计保存在被 Git 忽略的 `.gamecreator/qa`。

## 可点击原型场景

五套内置模板均已填充「原型设计」。创建示例项目后，直接进入该模块点击「从头预览」，无需再手工生成场景组。

| 模板 | 场景数 | 可体验的主要路线 |
| --- | ---: | --- |
| 植物大战僵尸 | 17 | 选卡、草坪种植结果、三波守关、暂停、胜负、首领分支、无尽整备、花园培育与收获 |
| 星露谷物语 | 19 | 农场与村庄、采购、耕作与跨日成长、委托、钓鱼、矿洞、出货、次日安排与七日回顾 |
| 空洞骑士 | 15 | 四房间地图、长椅、冲刺试炼、尖刺门槛、永久近路、首领二阶段、死亡和残影回收 |
| 极乐迪斯科 | 31 | 五处调查地点、人物对话与内心声音、红白检定、替代线索、思想、日程、三种阶段报告 |
| 吸血鬼幸存者 | 24 | 角色与图鉴、荒原、三选一、构筑、重抽放逐、宝箱进化、终局收益、永久强化 |

场景使用已有的空间对象和玩法核心节点。没有交付素材的部分以文字和色块表现，不伪造美术交付记录。各页是可点击的设计快照；分支结果通过「演示」按钮选择，条件由预览者确认，金币、战斗与时间没有自动模拟。原有制作清单和试玩状态仍未完成、未测试。

`node scripts/build-prototype-scenes.mjs` 可按版本化脚本重建五套场景，仅替换示例 JSON 中的 `prototypeDesign`。该命令不访问本机项目或 ProjectCache。场景使用稳定 ID，重复生成结果一致。

`node --test tests/prototype-scene-content.test.mjs` 校验全部场景可从入口到达、可返回主界面、引用有效、界面元素没有超出画面，并检查导入导出保真。构建后运行 `tests/desktop-prototype-scenes.cjs` 验证五条主要路线及所有场景实际渲染。
