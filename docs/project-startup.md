# 工程协作入口与成员凭证同步

“项目管理”包含项目规范、工程连接、人员分配、项目排期、任务清单、项目内容同步和工程同步。原“项目启动”已并入工程同步；首次准备与日常更新使用同一套同步配置、待同步变更、开发反馈和同步记录。数据配置与数据同步归入“数据管理”。

工程同步准备和更新协作文件，不启动引擎进程，也不自动创建游戏场景。AI 以引擎工程为主要工作目录，通过实际运行验证设计；GameCreator 项目保存正式设计、分工、排期与验收记录。

## 准备与初始化

1. 将 GameCreator 项目保存到独立文件夹。
2. 在“工程连接”选择引擎并保存工程根目录。切换页面会保留未保存的连接草稿，保存前禁止初始化或工程同步。
3. 在“人员分配”创建开发者及长期令牌。至少一位启用的制作人需要制作管理岗位、项目范围、`project_write` 和内容模块授权。制作人可以没有具体任务。
4. 所有启用的开发者都需要启用的岗位和一个有效长期令牌。本机必须能从凭证保管库读取私钥；旧令牌仅有公开信息时，先导入已保存凭证或更换令牌。初始化不自动生成或更换身份。
5. 在“工程同步 → 同步配置”开启开发协作与成员凭证同步，设置协作入口子目录，默认 `gamecreator`；设置设计文档子目录，默认 `docs/gamecreator`。二者都相对于保存的引擎根目录，不能越界或与素材等输出目录重叠。
6. 保存同步配置后预览同步变更，检查文档、工作说明和私有凭证的新增、更新、冲突及待移除内容。每项冲突必须明确保留或替换；删除旧路径另需勾选。确认后点击“同步到工程”。

如工程清单属于其他 GameCreator 项目，先到“工程同步”核对归属并按现有重新绑定流程处理；凭证同步不能绕过归属检查。

## 输出位置

默认结构：

```text
引擎工程/
  .gitignore                         # 加入 /gamecreator/personal/
  gamecreator/
    README.md                        # 完整工作流与目标 GameCreator 路径
    project.json                     # 项目身份、公开上下文与 authoring 路径
    personal/
      README.md                      # 成员名称与凭证文件对应关系
      <成员ID>.json                   # 该成员的完整私有凭证
      .gitignore                     # 忽略此目录内容
      .gdignore                      # Godot 工程中排除私有凭证资源
    context/                         # 开发反馈所用公开上下文
    feedback/                        # 引擎开发反馈
    receipts/                        # 反馈处理回执
  docs/gamecreator/
    README.md                        # 工作流、目录位置与分类索引
    modules/
      overview.md
      project-management/            # 本项目自定义规范、工程连接、排期、人员
      gameplay/                      # 玩法、关卡、原型、数值分析
      development/                   # 功能系统、开发工具、程序框架
      content/                       # 素材、故事与编排
      data-engine/                   # 数据、枚举、配置规范
```

协作入口也可以设置为例如 `team`。此时入口 README 和 personal 位于 `team/`，README 链接到固定的 `gamecreator/README.md`。后续普通工程同步会继续维护此入口，文档目录变化后同步更新链接。开发反馈仍使用 `gamecreator/feedback`，不迁移反馈协议目录。

开启成员凭证同步后，同时更新**绑定的 GameCreator 项目**中的 `GAMECREATOR_GUIDE.md`、`PROJECT_STANDARDS.md`、`ai/README.md`、编写上下文、模板和校验提交脚本。内容编写工具仍属于这个管理项目，没有复制到引擎目录运行。

## 日常工作循环

1. AI 从引擎中的入口 README 开始，核对项目 ID、引擎目录和 GameCreator 项目目录，读取规范与当前文档。
2. 设计需要新增、重组或修改多个模块时，进入 README 指定的 GameCreator 项目目录，阅读 `GAMECREATOR_GUIDE.md` 和 `ai/README.md`。刷新协作文件，基于当前快照编写内容批次，校验并使用自己的凭证签名提交到 `ai/changes`。
3. 管理者在“项目内容同步 → 设计提交”读取并检查变更、处理冲突后应用。AI 查看该项目 `ai/receipts` 确认结果。
4. 将通过检查的设计文档与协作上下文同步回引擎；正式配置文件另走“数据同步”。开发者在引擎中实现和测试。
5. 进度、验收结论及现有需求建议写入引擎 `gamecreator/feedback`，在“工程同步 → 开发反馈”处理；后续再同步新的进度和上下文。

两套提交位置、快照与格式不可混用。直接编辑导出的 Markdown 不会回写 GameCreator。实际引擎效果为设计判断提供依据，代码当前行为不自动成为已验收要求。

## 重复执行与保护

- 重复同步沿用已有身份和令牌，内容相同的凭证不重写。新增成员或更换令牌后可再次预览同步。
- 私钥内容不进入公共文档、预览、历史或备份；预览和记录只包含成员、路径与处理状态。同步在写入凭证前添加 Git 忽略规则；已有自定义规则保留。目录本身不提供开发者之间的文件访问隔离，每位 AI 只使用分配给自己的凭证。
- 外部修改过或未登记的凭证列为冲突，需要选择保留或替换。停用成员、撤销令牌或迁移入口目录后，旧受管凭证列为待移除；明确勾选后才删除，私钥不备份。被保留的旧位置会继续跟踪。关闭成员凭证同步会保留现有文件；实际权限以客户端当前授权为准。
- 普通文档继续使用冲突处理、备份、过期预览与中断恢复。旧平铺文档会列为待移除项，未经明确选择不会删除。
- 只有全部步骤成功才保存协作同步完成记录。凭证处理记录保存在管理项目中，在工程同步记录页统一查看。若文档已同步而后续凭证写入失败，页面报告失败，修复原因后重新预览同步；不会重新签发令牌或把部分完成标为成功。
- 目录搬迁后重新保存工程连接并同步文档，更新 README 中的具体位置。

## 验证

`node --test tests/project-startup.test.cjs` 覆盖初始化、重复执行、自定义入口、令牌与文件冲突、归属和旧文档迁移。构建后运行 `node tests/desktop-project-startup.cjs` 验证客户端入口、准备状态、初始化、重启与路径显示。测试只使用独立临时项目。
