# 使用帮助与项目操作入口

侧栏底部的“使用帮助”属于软件级入口，无需创建或打开项目。工作流总览、美术工作流、操作说明和通用规范直接显示在工作区主面板，侧栏与页签同步选中，支持复制、下载和规则范围切换。点击其他模块即可继续工作；未选择项目时也可返回项目选择。

| 入口 | 内容 |
| --- | --- |
| 使用帮助 → 工作流总览 | 三个目录、初始化、设计提交、引擎开发、反馈与验收迭代的完整流程 |
| 使用帮助 → 美术工作流 | 素材需求、风格、技术方案、任务派发、制作接入、反馈与验收联动 |
| 使用帮助 → 操作说明 | 固定工作流、目录说明、项目编写协议与权限含义 |
| 使用帮助 → 通用规范 | 内置更新原则、模块组织规则与更新步骤 |
| 项目管理 → 项目规范 | 当前项目的整体约定、各模块约定、当前结构检查 |
| 数据与同步 → 项目内容同步 | 更新协作文件、读取设计提交、预览差异、处理冲突、应用与恢复、处理记录 |
| 人员分配 → 权限查询 | 当前开发者的实际启用状态、授权模块与有效期 |

项目内容同步保留“设计提交”和“处理记录”两个页签，使用原有编写协议和存档历史。设计文件仍在 GameCreator 项目的 `ai/changes`，回执仍在 `ai/receipts`；应用成功后返回项目内容同步。工程开发反馈和配置数据导入导出继续分别使用工程同步、数据同步。

工作流总览的正文维护在 `docs/workflow-overview.md`，客户端直接使用同一份文档。支持复制全文和下载 `GAMECREATOR_WORKFLOW.md`；作为软件通用帮助，不额外写入项目或引擎目录。

美术工作流的正文维护在 `docs/art-workflow.md`，同样在主面板阅读，支持复制全文和下载 `GAMECREATOR_ART_WORKFLOW.md`。正文区分现有功能与样例先行、独立审核任务等制作建议，不将建议描述为系统强制审批关卡。

## 文档生成

- GameCreator 项目根目录保存 `GAMECREATOR_GUIDE.md`，以及包含内置规则和本项目约定的 `PROJECT_STANDARDS.md`。新建项目、更新协作文件和项目初始化时生成或刷新。原始项目规范存档格式不变。
- 引擎只生成当前项目的自定义规范，位于 `<文档目录>/modules/project-management/standards.md`。项目整体约定与所有非空模块约定都会输出，没有填写时明确说明暂无自定义规范。
- 引擎 README、协作说明、成员说明链接到上述单一规范文件，并提供管理项目完整文档的位置。即使只开启开发协作，也生成该规范文件。
- 引擎不再生成独立的完整使用说明或通用规范副本；旧受管副本列入同步预览，只有明确选择才移除，手工修改仍按冲突处理。旧反馈快照保留用于审核历史反馈。
- 项目全局搜索仅索引当前项目填写的约定；内置规则通过使用帮助查阅。

## 验证

构建后运行 `node tests/desktop-software-help.cjs` 验证无项目帮助、只读行为和窄窗口。`desktop-project-authoring.cjs`、`desktop-project-standards.cjs`、`desktop-navigation.cjs` 验证操作迁移、回写、权限查询与导航；`project-startup.test.cjs` 验证完整规范、自定义规范、清空约定、仅开发协作同步及旧文档迁移。
