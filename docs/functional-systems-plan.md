# 功能系统模块实施计划

状态：已实施并验收。实施前检查点为 `a42dcc5`（空间布局与时间轴）。本次构建、69项模型测试、功能系统桌面验收及3套原有玩法桌面回归均通过。

## 目标与组织方式

在“玩法设计”旁增加“功能系统”，帮助程序把分散的玩法需求归并为有归属、可复用、可追踪的实现模块。

- 玩法描述体验、场景和设计目标，例如“跨越裂隙”和“通过试炼获得冲刺”。
- 系统定义职责与边界，例如技能系统、角色移动系统、战斗系统、关卡系统、进度与存档系统。
- 功能是系统提供的具体能力，例如技能系统中的玩家冲刺、聚焦治疗，移动系统中的水平位移、落地检测。
- 一个功能只归属一个系统，可以支持多个玩法；一个玩法也可以使用多个系统的功能。
- 玩法、规则与配置通过稳定 ID 关联；同名文字只作为查找线索，不自动视为同一功能。

以空洞骑士为例：移动教学、试炼奖励和裂隙通行都关联同一个“玩家冲刺”功能，并分别说明“使用”“解锁”“要求已获得”的场景。玩家冲刺的执行约束集中维护，数值通过配置引用展示；各玩法保留其体验目标。首领的冲刺斩击保留独立技能定义，可与玩家冲刺共同依赖移动系统的位移能力。

## 第一阶段：建立系统与功能目录

新增导航“功能系统”。界面左侧为系统及其功能列表，右侧为详情，支持搜索、筛选、新建、重命名、移动归属、归档和恢复。创建只要求名称，其他信息可逐步补全。

系统详情包含职责、边界、功能列表、关联玩法及汇总依赖。功能详情包含用途、触发/输入、结果/输出、执行条件、打断与失败处理、关键状态、关联配置和实现状态。实现状态独立于玩法验证状态，不把设计资料完整等同于代码完成。

建议页签：功能说明、依赖关系、关联玩法。首次打开空项目显示空目录。

## 第二阶段：连接玩法与功能

玩法详情新增“实现功能”引用区，支持选择已有功能和跳转详情；在功能侧也可关联玩法，并填写此处如何使用该功能。反向引用由同一份关系数据计算，避免两边各存一份产生分歧。

可附加具体玩法规则、状态或时间事件作为需求来源。来源重命名实时解析名称，失效或归档时保留关系并提示。配置引用支持表以及可选的记录/字段，展示当前值，不复制一份独立参数。

现有玩法页签“系统关系”改称“玩法关联”，保留原有关系及数据；程序模块间的协作在“功能系统”中表达。

## 第三阶段：梳理程序依赖与影响

功能之间的关系区分调用功能、读取数据、订阅事件，并填写依赖目的。系统级图由这些明细聚合产生，点开系统或功能才展开相关关系；默认聚焦当前节点和直接上下游，可切换关系类型。

每个功能同时显示“依赖谁”和“谁使用它”，并列出受影响玩法。对自身引用、重复关系、失效对象进行检查；调用依赖中的循环显示提示及涉及路径，事件反馈不直接当作非法循环。

归档保留引用，删除被引用对象前必须解除或替换关系。更改功能归属时保留功能 ID，已有玩法引用仍有效。

## 第四阶段：保存与导出

新增按项目 ID 隔离的功能系统存档，使用独立 schema，统一保存系统、功能、依赖和玩法引用。延续现有自动保存、原子备份、损坏保护和旧内容冲突检测。

保存失败时保留修改并支持重试，接入全局保存提示、项目切换、测试工作区切换和退出保护；不允许带未保存内容导出。新模块默认空存档，旧玩法 schema 3、已有 ID 和原型数据保持可读。

AI 文档增加按系统组织的程序实现说明：功能定义、输入输出、依赖、配置引用及需求来源；玩法章节列出关联功能，实现双向查阅。引用失效在界面与导出中均明确标记。

## 第五阶段：用空洞骑士整理完整案例

按现有需求建立输入、角色移动、技能、战斗、关卡、进度与存档等系统；仅建立实际需要的功能条目。

先以玩家冲刺完成一条端到端链路：输入动作 → 技能释放判定 → 移动位移 → 结束/打断 → 冷却与空中次数恢复。试炼负责发出能力解锁需求，进度保存解锁结果，裂隙玩法引用其能力门槛。

将多个玩法中重复的冲刺执行说明归并为功能定义，玩法保留场景语境和引用。随后以聚焦治疗、伤害结算、房间切换、死亡回收验证系统间协作。整理过程不自动把所有同名词汇合并，不自动生成已实现状态。

## 验收标准

1. 在技能系统中只维护一份玩家冲刺，移动教学、试炼和裂隙玩法能跳到同一条目；条目反向显示三个场景及使用方式。
2. 重命名或移动冲刺归属后，所有关联仍有效；玩家冲刺与首领冲刺斩击保持独立定义，共享基础位移依赖。
3. 修改所引用配置后，功能展示及导出使用当前值；删除或归档来源有明确提示。
4. 聚焦查看冲刺时可以辨认直接依赖、使用者与受影响玩法，不需要阅读整张项目图。
5. 保存失败、过期写入、损坏存档均不覆盖已保存内容；切换项目、测试工作区和重启后数据各自完整。
6. 构建、模型测试与桌面流程验收通过；现有植物大战僵尸、星露谷、空洞骑士原型及导出回归通过。

## 本次交付结果

空洞骑士案例已整理为9个系统、17项功能、48条程序依赖、35条玩法引用和54条实时配置引用。玩家冲刺由移动教学、试炼授予、裂隙门槛共用一个定义，首领冲刺斩击归入敌人技能系统，决策与重置归入敌人 AI 系统。6份玩法正文完成公共执行约束归并，原有规则图、状态图、时间轴及30项未测试的试玩记录保持完整。

实测覆盖：双方维护同一引用、规则/状态/时间事件准确跳转、改名与归属移动、归档只读和删除保护、实时配置值、保存失败保留草稿/重试/禁止退出登录、过期与损坏存档、项目隔离、重启恢复和完整导出一次。真实项目核验确认植物大战僵尸与星露谷存档未被改变。
