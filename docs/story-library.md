# 故事文档库

故事文档用于长篇设定和剧情写作；玩法核心仍负责玩法流程，故事编排负责可运行的叙事节点。

## 浏览与写作

- 分类首页提供世界观、角色、地点、阵营、主线、支线入口，保留项目原有分类。分类名称保存在每份文档中；新建时可输入自定义分类，也可在属性中移动文档。空的建议分类不创建任何内容。
- 支持标题、正文、摘要、标签搜索，状态/归档筛选、标题/最近编辑排序。
- 点击分类进入文档卡片，打开后显示同分类目录、正文和属性栏。目录和属性栏可收起，专注写作隐藏两侧栏。
- 模板生成角色、地点、章节、世界观的 Markdown 提纲，也可从空白开始。模板不会虚构关联条目。
- 编辑、阅读、分栏预览支持基础 Markdown：标题、粗体、斜体、列表、引用、链接、分隔线和围栏代码。工具栏保留原生撤销/重做。不是完整 CommonMark 编辑器；不执行 HTML，链接仅接受 http/https/mailto。
- 正文目录由 Markdown 标题生成，点击可定位。旧的手写 `outlines` 保留为“创作提纲”，不会自动覆盖。
- 复制生成新 ID；归档保留正文、关联与历史，默认筛选隐藏归档项，可恢复。

## 保存与兼容

原 `gamecreator.workspace.v1:<项目>:stories` 数组及文档 ID 不变。新增可选字段：`format`（plain/markdown）、`archived`、`updatedAt`、`references`。没有 format 的旧正文按纯文本显示，打开不会写入、改写或补默认字段。

本机视图保存在 `gamecreator.story-view.v1:<工作区>`，包含分类、文档、面板、阅读模式与滚动位置。团队工作区键包含服务器、用户、项目，个人阅读位置不提交到团队，也不进入项目包。

本地写入先检查磁盘版本，遇到磁盘错误或其他窗口更新会保留当前草稿，提供重试、导出草稿、重新读取；未保存时阻止切换项目及离开工作区。损坏存档停止编辑，可重新读取。

团队 API 11 支持新增字段，继续使用原故事修订号、草稿、冲突检查和历史表。旧客户端缺少新增字段的更新会保留服务端已有值。连接旧服务端时，新客户端禁用新增字段操作，并阻止会丢字段的导入/发布。

## 引用

`references` 记录 `{kind,targetId,label,sourceOnly?}`。本地可关联故事、玩法、程序功能、素材需求/资产、地图、故事角色/编排、任务；团队仅提供当前已共享可访问的故事和玩法。失效或未启用的目标保留名称但不跳转，旧文字关联单独保留。

“引用本文”从故事引用、玩法链接、地图对象引用和任务引用中计算，不依靠正文名称猜测。全局搜索忽略仅来源引用。

故事导入/项目发布会重新生成团队故事 ID，批次内及以前已导入的故事引用通过来源身份映射。未映射的目标保留为 sourceOnly，不会误连团队中同 ID 的对象。重复导入不覆盖已编辑的团队文档；先前未映射的来源引用不会在后续导入时自动重写。

## 验证

- `npm run build`
- `npm run test:story-library`：旧数据、模板/分类、Markdown、五个原型的真实文件夹往返、团队字段/权限/历史/重启/导入。
- `npm run test:collaboration`：完整团队 API 回归。
- `node tests/desktop-story-library.cjs`：隔离 Electron 项目，五原型浏览、模板/撤销/预览/大纲/引用/归档、磁盘失败重试、窄窗口、重启。
- `node tests/desktop-team-story-library.cjs`：隔离真实团队客户端，服务端 ID、引用跳转、归档/恢复、冲突、历史、只读与重启。
- `node tests/desktop-global-search.cjs` 和 `node tests/desktop-team-global-search.cjs`：搜索定位与普通导航。

桌面验证先构建；无本地 Playwright 时用 `GAMECREATOR_PLAYWRIGHT_PATH` 指向运行时包。所有测试使用临时存档，不修改用户项目。
