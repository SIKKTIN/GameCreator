排期仅覆盖当前原型文档规定的范围。顺序为：确认范围 → 灰盒核心 → 内容闭环 → 表现整合 → 实测与修复。程序工作最多两项并行，美术最多一项；测试窗口允许团队共同参与。

每项制作任务均有起止日期、前置依赖、里程碑与验收条件。全部玩法文档、程序功能、美术需求和原型场景都有相应任务关联。负责人、实际日期、验收结果保持空白；任务均为“待开始”，里程碑均为“计划中”。尚未完成的前置任务会显示依赖提醒，这是计划状态，不代表发生故障。

- 植物大战僵尸：种植经济、同路战斗、三波调度、暂停与重开；重点检查一次性生成、收集和胜负结算。
- 星露谷：工具与作物、天气与日结算、背包经济、NPC 委托和七日目标；安排完整七日经营与存读档回归。
- 空洞骑士：移动手感、永久冲刺、四房间门槛与近路、双阶段首领、长椅与残影；安排路线可达和死亡恢复回归。
- 极乐迪斯科：世界事务、对话声音、红白检定、两天日程与思想、取证与三结局；按分支矩阵验证失败继续和快照恢复。
- 吸血鬼幸存者：自由移动与自动攻击、升级构筑、三种进化、怪潮、局外成长与结算；包含真实三十分钟试玩和高密度性能测试。

内置示例 JSON 的可选 `projectSchedule` 保存排期。新建示例副本及文件夹包转移会保留完整任务和里程碑；老示例没有该字段仍可导入为空排期。导入不会按当天自动挪动日期，也不会自动把设计、程序或美术标记为完成。

现有本地副本的补充只针对项目列表内的匹配原型，并先备份存档；已有自定义排期不覆盖。`ProjectCache` 的五个文件夹包同步增加排期文件及清单校验值，不改其他模块内容。
