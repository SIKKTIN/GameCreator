# 本地数据持久化

## 保存位置

Electron 客户端将工作区数据保存在 GameCreator 根目录的 `.gamecreator/`：

- `art-files/`：按正式项目或测试工作区隔离的交付文件副本，历史版本持续保留。
- `storage/`：当前存档，每个键一个 JSON 文件，文件名由键的 SHA-256 生成。
- `storage/*.bak`：该存档上一次成功写入前的副本。
- `legacy-backups/`：首次升级时找到的旧版浏览器存档，按来源地址完整备份。
- `legacy-migration.json`：旧版迁移结果和采用的来源地址。

可以在关闭客户端后复制整个 `.gamecreator/` 目录进行备份。此目录不提交到 Git。更换 GameCreator 安装目录时也应一并复制。
存档不会写入 Withdraw 游戏工程或修改 Lua 源文件。

## 保存内容

项目列表、当前选择和正式/测试模式会保存到 `gamecreator.projects.v1`。该存储键保持不变，列表内容使用 schema 2。每个正式项目在列表中保有自己的引擎配置，包括工程目录、枚举目录、数据目录和其他选项。重启恢复最后选择的项目；在测试模式下退出时，进入本地工作区后恢复有效的测试会话。

下列内容按固定项目标识隔离。新项目使用 `project-<UUID>` 标识；工程目录不决定项目身份，改名、绑定、更换或清空工程目录均保留原存档。多个项目可以引用同一个工程目录，内容仍独立保存：

| 存档内容 | 存储键 |
| --- | --- |
| 枚举稳定版本、候选版本、审核决定、发布与迁移历史、配置表字段和数据记录 | `gamecreator.enum-versions.v1:<项目标识>` |
| 玩法设计、依赖关系、条件规则、状态流程、空间布局、时间轴、原型清单、验证记录和关联 | `gamecreator.workspace.v1:<项目标识>:gameplay` |
| 功能系统、功能规格、程序依赖与玩法引用（独立 schema 1） | `gamecreator.workspace.v1:<项目标识>:functional-systems` |
| 美术需求、交付版本、审核、采用与来源关系（独立 schema 1） | `gamecreator.workspace.v1:<项目标识>:art-assets` |
| 配置表目录和显示名称 | `gamecreator.workspace.v1:<项目标识>:definitions` |
| 项目信息、故事文档、里程碑 | `gamecreator.workspace.v1:<项目标识>:project`、`:stories`、`:milestones` |

配置表目录与引擎设置由各项目独立保存。左上角项目列表切换时会一起加载所选项目的内容和配置。新建项目只需填写名称，默认使用空记录、空故事和空里程碑，保留默认配置表与字段模板。无需配置外部目录即可开始整理内容。

工程目录、枚举目录和其他引擎选项在“引擎设置”中配置。编辑内容先作为草稿，点击“保存设置”后才提交；清空工程目录并保存表示暂不连接外部工程。未连接时不扫描枚举，也不报告连接失败，已有内容继续保存在同一项目下。

已有 schema 1 项目列表升级到 schema 2 时，保留项目 ID、当前选择、正式/测试模式和各项目配置。旧 ID 即使包含工程路径，也继续作为固定标识使用；原枚举与工作区存储键不改名、不搬迁，因此升级和后续更换目录不会丢失旧存档。

首次升级到项目列表时，将旧 `gamecreator.engine-config.v1` 中的工程注册为现有项目，并保留原项目名称与内容。旧全局 `gamecreator.dataset-definitions.v1` 仅在原项目尚无独立表目录存档时迁入该项目，新增项目不会继承这份全局表目录。旧键保留，已有独立存档不覆盖。

操作方式见 [项目切换与独立存档](project-switching.md)。

项目内容修改后自动保存，顶部显示保存状态；引擎设置草稿需点击“保存设置”提交。读取或写入失败会提示错误，失败的修改不会显示为已保存。
登录会话仍由当前浏览器来源保存，重启可能需要重新登录，工作区存档不受影响。

## 为什么旧版本重启后像是丢失

旧桌面服务每次分配随机 HTTP 端口，而 localStorage 以完整来源地址隔离。
旧记录通常仍存在于 Electron 浏览器配置中，但新端口无法读取它们。

新版通过受限的 Electron IPC 直接读写磁盘，随机端口不再影响持久化。
首次升级会从旧浏览器数据库发现本机来源地址，再由 Chromium 读取对应的实际存档。
同一工程有多份旧记录时，优先采用包含已发布版本的记录，再按快照时间和修订号选择；所有发现的旧副本同时备份，现有磁盘记录不被迁移覆盖。
已清除的浏览器数据，以及旧版本从未保存到 localStorage 的故事/项目信息无法自动恢复。

## 写入与故障保护

桌面只允许一个实例写入同一用户配置。
枚举发布仍沿用原有修订号检查和 Web Locks；稳定版本与配置迁移在同一存档提交。
磁盘写入先写临时文件并刷新，再原子替换目标文件；保留上一版备份。
现有存档损坏时停止读取/覆盖，显示错误，不静默重置为空存档。

浏览器开发模式仍使用 localStorage，受浏览器、站点地址和端口隔离；磁盘存档是 Electron 客户端能力。

## 验证

```powershell
npm run build
node --test tests/enum-bindings.test.mjs tests/enum-versions.test.mjs tests/desktop-storage.test.cjs
```

真实 Electron 重启验收需可用的 Playwright（可通过 `GAMECREATOR_PLAYWRIGHT_PATH` 指定模块目录）：

```powershell
node tests/desktop-restart.cjs
```

该测试使用临时独立用户配置和存档目录，验证旧数据迁移、实际编辑，以及不同端口下的连续重启恢复，不读取或修改用户真实存档。

玩法内容独立使用 schema 3。读取 schema 1 时补充空的结构化关系、规则和状态流程；读取 schema 1/2 时再补充空网格与时间轴，仅在首次编辑时保存升级。保留原玩法与内部 ID、文本、制作和验证数据。图形查看、手动路径预览和时间播放/游标不改写存档。
