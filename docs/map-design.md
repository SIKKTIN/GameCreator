# 地图设计

地图设计是本地项目的可选模块，在「工作区设置 → 添加地图设计」启用。关闭只隐藏导航入口，保留地图、连接和原型引用；项目文件夹导出、导入与重启都会保留启用状态。旧项目和其余原型默认不启用，空洞骑士、星露谷的新示例副本默认启用并带有内容。

## 世界与地图

- **世界总览**：选择整个世界的「俯视平面」或「横版高度空间」，按统一比例展示房间边界、内部地形和出入口。拖动房间改变实际世界位置，双击进入内部布局。俯视的纵轴向南，横版的纵轴向下；切换类型保留位置与尺寸。
- **地图画布**：编辑房间内部的局部布局。网格吸附和自由二维共用局部坐标，切换视图不改写对象位置。整体视角由世界总览统一设置。
- **图层**：可新增、命名、隐藏、锁定和调整前后顺序。隐藏影响编辑画布，完整地图仍参与原型；删除图层前先移走对象。地形、障碍、装饰、人物、建筑、资源、敌人、任务点、出入口和标记均可放置、拖动和编辑尺寸。
- **内容关联**：对象可以关联玩法、任务、故事文档、项目人物、美术资产和原型场景。引用保存目标身份，完整内容由对应模块管理。失效引用保留在草稿中并报告检查问题。
- **通路预演**：选择起点，根据空间方向逐步前进。几何或移动范围不满足时不能通行；额外的钥匙、剧情等文字条件由预演者确认。预演不更改故事状态或任务进度。

画布支持滚轮缩放、右键平移、适应全部和定位所选对象。第一版绘制设计布局与交互标记，不执行角色移动、碰撞、寻路或战斗。

## 世界坐标与通行方式

每个房间具有世界位置 `placement.x/y` 和局部单位换算比例 `placement.scale`。内部坐标转换规则为：世界坐标 = 房间世界位置 + 局部坐标 × 换算比例。房间真实尺寸由内部行列、每格尺寸及换算比例得出，不使用固定大小的卡片。总览拖动或方向键移动只保存房间位置；内部对象与引用玩法的坐标保持。拖动过程中仅预览，松开保存一次，Esc 取消。

出入口绑定具体对象，朝向选择左、右、顶部、底部或对象中心。新建通路根据房间相对位置初始化朝向，之后固定保存；拖动房间、切换视角或移动绑定对象都不会让出口自动换边。「按当前布局设置朝向」可主动重新设置两端；重合且无法判断方向的房间需要手动指定。总览端点短线标示朝向，选中连接时显示两端侧面。边缘锚点保留对象沿该边的位置，连线落在这些锚点上。

普通跨房间通路要求两端左右或上下相对，并且目标房间位于出口外侧；顶部连左侧、背向连接、需要穿过房间的连接及超出边缘的锚点都会报告具体原因并阻止预演与生成原型中的跳转。朝向正确后，可以通过「移动终点地图以对齐出入口」精确移动终点房间。调整朝向只改变连接，不移动内部对象；对齐只移动目标房间，不改动局部布局。弯折通道需要用实际中间地图表达，室内场景跳转或传送需明确选择相应移动方式。不同房间范围重叠会提示检查。

横版中，下层 C 通往上层 A 应设置跳跃或攀爬；反向可独立设置下落。即使上下房间的边缘恰好接触，也仍保留上／下方向，不能按水平步行处理。跳跃、攀爬和下落分别受连接中设定的最大上升、水平跨度和最大下落高度约束。这些是出入口间的设计范围检查，不模拟房间内完整的平台路径或运动物理。

俯视中，纵向表示南北，普通通路要求出入口对齐，不套用重力与跳跃规则。「传送」类型或「传送／场景门」移动方式可跨越空间距离，仍需要有效的两端对象。已有文字解锁条件独立保留。

旧版总览的 `x/y` 保留为原连接图坐标，读取时按旧房间尺寸统一缩放推导新的 `placement`，不会将屏幕像素直接作为世界单位。转换保留相对排列和全部内部数据，实际读取不写盘，首次编辑时与其他更改一起保存；混合比例或原先随意排列的旧布局需继续调整衔接。已有世界坐标不会再次转换。缺少朝向或使用旧版 auto 的连接，按房间布局一次性补齐并固定朝向，不再根据对象最近的房间边缘猜测；已有明确朝向保持不变，若仅一端已指定则按其相对侧补齐另一端。普通上下房间得到顶部／底部，左右房间得到左侧／右侧；传送与同一房间内部连接默认使用对象中心。补齐与坐标转换都不在读取时写盘，在首次编辑成功保存后落盘；保存失败仍可重试，原始存档保持。

## 空间来源与原型

每张地图可以是独立布局，也可以引用既有玩法的根空间或某个房间。引用对象实时读取来源，地图不保存第二份对象坐标。来源图层默认锁定；解锁后拖动来源对象会直接保存到原玩法存档，并同步影响原有空间预览及原型。完整来源属性可通过「编辑来源玩法」打开。

地图新增的对象在自身图层保存，可与来源对象共同展示。来源图层始终在本地图层下面；图层显隐与锁定属于编辑状态。更换来源不会迁移对象，已有出入口或原型热点失效时需重新关联。地图自身行列与单位用于独立布局；有来源时采用来源的尺寸与单位。

「生成地图原型」添加一组引用当前地图的场景，生成沿连接跳转的按钮，保留原有原型场景。新增按钮还绑定世界通路 ID 与正反方向；移动房间、调整移动限制、改变方向或文字条件后，预览实时检查最新设计。更改连接的目标地图或对象需要重新关联或生成，删除连接后不会继续沿失效通路跳转。按钮文案和场景编排仍可编辑；也可明确将按钮转为独立场景跳转。升级前已经生成的旧按钮保持原有独立动作，可重新生成以接入世界检查。

原型的「地图来源」也可手动选择，使用「编辑来源地图」返回。关闭地图模块后，已引用地图的原型仍能读取保存的数据。

示例的世界连接由既有玩法房间图初始化，后续在地图模块独立编排；已有玩法房间图保留。房间中的实体位置始终来自原玩法空间。地图不是第二套任务或故事状态系统，通行条件在第一版以设计说明保存，并由预演者确认。

## 存档与保护

地图存档键为 `gamecreator.workspace.v1:<projectId>:map-design`，结构版本 `schema: 1`。内容包括 `enabled`、`maps`、`connections`，以及兼容旧存档的可选 `world`（类型、世界单位、吸附步长）。各地图新增可选 `placement`；连接新增可选 `fromSide/toSide/travel`。世界位置与局部对象位置分别存储，前端与桌面导入边界校验所有新增字段。

写入前校验格式并比较读取时的原始存档，检测另一个窗口的修改。写入失败保留草稿，阻止切项目、退出测试、登出和关闭窗口丢失编辑；可导出草稿、重试或重新读取。损坏的存档停止写入，不会自动重置为空白。地图／出入口仍被连接或原型引用时不能删除。上限为 100 张地图、500 条连接、每图 30 层和 300 个本地对象。

完整项目文件夹包含 `data/map-design.json`，关闭的模块也会迁移内容。旧文件夹缺少此文件时得到空白、未启用的模块。AI 文档仅导出已启用地图的区域、实际对象布局、关联和连接说明。模块暂限本地项目，与故事编排的共享范围相同。

## 示例与验证

`node scripts/build-map-examples.mjs` 只更新空洞骑士、星露谷示例的 `mapDesign`，不会重写其玩法或原型场景。空洞骑士包含 4 张地图、8 条有向通路；星露谷包含农场、村庄和 1 条双向连接。`node scripts/sync-map-validator.mjs` 同步 Electron 文件夹边界使用的结构校验器。

模型与便携测试：`node --test tests/map-design.test.mjs tests/map-world.test.mjs`。客户端测试：`node tests/desktop-map-design.cjs` 、`node tests/desktop-map-world.cjs` 与 `node tests/desktop-map-portals.cjs`（可通过 `GAMECREATOR_PLAYWRIGHT_PATH` 指定 Playwright），使用隔离的临时项目和用户目录。
