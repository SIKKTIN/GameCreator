# 地图设计

地图设计是本地项目的可选模块，在「工作区设置 → 添加地图设计」启用。关闭只隐藏导航入口，保留地图、连接和原型引用；项目文件夹导出、导入与重启都会保留启用状态。旧项目和其余原型默认不启用，空洞骑士、星露谷的新示例副本默认启用并带有内容。

## 世界与地图

- **世界总览**：选择整个世界的「俯视平面」或「横版高度空间」，按统一比例展示房间边界、内部地形和出入口。拖动房间改变实际世界位置，双击进入内部布局。俯视的纵轴向南，横版的纵轴向下；切换类型保留位置与尺寸。
- **地图画布**：编辑房间内部的局部布局。网格吸附和自由二维共用局部坐标，切换视图不改写对象位置。整体视角由世界总览统一设置。
- **图层**：可新增、命名、隐藏、锁定和调整前后顺序。隐藏影响编辑画布，完整地图仍参与原型；删除图层前先移走对象。地形、障碍、装饰、人物、建筑、资源、敌人、任务点、出入口和标记均可放置、拖动和编辑尺寸。
- **内容关联**：对象可以关联玩法、任务、故事文档、项目人物、美术资产和原型场景。引用保存目标身份，完整内容由对应模块管理。失效引用保留在草稿中并报告检查问题。
- **通路预演**：选择起点，根据空间方向逐步前进。几何或移动范围不满足时不能通行；额外的钥匙、剧情等文字条件由预演者确认。预演不更改故事状态或任务进度。

画布支持滚轮缩放、右键平移、适应全部和定位所选对象。通行检查采用可配置矩形角色，验证静态矩形地形、支撑、单向平台、梯子与设计级行进路线；不运行战斗或游戏引擎的完整物理模拟。

## 世界坐标与通行方式

每个房间具有世界位置 `placement.x/y` 和局部单位换算比例 `placement.scale`。内部坐标转换规则为：世界坐标 = 房间世界位置 + 局部坐标 × 换算比例。房间真实尺寸由内部行列、每格尺寸及换算比例得出，不使用固定大小的卡片。总览拖动或方向键移动只保存房间位置；内部对象与引用玩法的坐标保持。拖动过程中仅预览，松开保存一次，Esc 取消。

物理开口独立于出发门与安全落点，保存房间边缘、沿边中心位置和宽度。地图画布支持添加、改名、调整、拖动开口；被通路引用时不能删除。世界总览按实际宽度显示开口，不将室内落点投影为物理出口。旧版的朝向设置仍可用于整理未完成的连接，绑定物理开口后以开口朝向为准。

通路选择两端物理开口，另选正向出发点、安全落点与返程出发点、安全落点。普通直通通道要求左右或上下相对，上下开口横坐标相同、左右开口高度相同。可以「对齐开口位置（保留房间）」调整终点开口沿边的位置，或「移动终点地图以对齐出入口」调整整个终点房间；两者不会挖空地形。弯折路线需要布置真实中间地图。连接段可设为开放空间、梯子或水平桥面，室内梯子和平台仍需实际布置。

同一个物理通道的往返只显示一条线。两个方向分别保存条件、移动方式、限制和落点。完全相反且没有歧义的相同对象连接可在读取时合并；使用不同门、落点的旧连接在属性中手动选择「合并往返为一条通路」。合并保留旧连接 ID 的方向别名，已有原型按钮仍能找到原来的方向和条件；普通路和永久近路不得按房间名称强行合并。

对象的通行属性可设为实体地形、单向平台、梯子、不阻挡。实体障碍默认阻挡，装饰和交互标记默认不阻挡；单向平台可从下方穿过，下降时会受到阻挡。图层隐藏只影响编辑显示，隐藏地形仍参与检查。选中未旋转矩形实体地形，指定开口并选择「沿此开口切开地形」，会实际拆分矩形、保留两侧地形。来源地形需要解锁，切割保存到同一份来源玩法坐标，地图和引用原型同步变化；开口标记本身不会自动切洞。

「通行角色与能力」设置角色宽高、可跨台阶、最大跳高、跳远和安全落差。横版路线检查地面支撑、净空、平台跳跃、梯子连续性和下落；从下层上去需要实际可达的上升路径，只有开口或宽松的跨度限制仍不能穿过地板。俯视路线检查连续地面道路和角色净空，不使用重力规则。通路预演到达新地图后会从上一次的落点检查下一条路线，不能通过点击另一个热点跳过室内隔墙；新生成的地图原型采用相同检查。

检查结果分为可通行、被阻挡、待完善。缺少物理开口、旋转或曲面通行地形、计算范围超限等情况不会当作已验证通行。封口、错位、净空不足或未找到路线会显示原因。选中通路并查看正向／返程，可在总览看到绿色行进路线或高亮阻挡地形；标签固定在画布信息区，避免堆叠在井口和房间名称上。「传送」或「传送／场景门」移动方式明确绕过普通空间路径检查，仍要求有效的地图与两端对象。


旧版总览的 `x/y` 保留为原连接图坐标，读取时按旧房间尺寸统一缩放推导新的 `placement`，不会将屏幕像素直接作为世界单位。旧项目不会自动切开地板、添加梯子或猜测物理开口。转换保留相对排列和全部内部数据，实际读取不写盘，首次编辑时与其他更改一起保存；混合比例或原先随意排列的旧布局需继续调整衔接。已有世界坐标不会再次转换。缺少朝向或使用旧版 auto 的连接，按房间布局一次性补齐并固定朝向，不再根据对象最近的房间边缘猜测；已有明确朝向保持不变，若仅一端已指定则按其相对侧补齐另一端。普通上下房间得到顶部／底部，左右房间得到左侧／右侧；传送与同一房间内部连接默认使用对象中心。补齐与坐标转换都不在读取时写盘，在首次编辑成功保存后落盘；保存失败仍可重试，原始存档保持。

## 空间来源与原型

每张地图可以是独立布局，也可以引用既有玩法的根空间或某个房间。引用对象实时读取来源，地图不保存第二份对象坐标。来源图层默认锁定；解锁后拖动来源对象会直接保存到原玩法存档，并同步影响原有空间预览及原型。完整来源属性可通过「编辑来源玩法」打开。

地图新增的对象在自身图层保存，可与来源对象共同展示。来源图层始终在本地图层下面；图层显隐与锁定属于编辑状态。更换来源不会迁移对象，已有出入口或原型热点失效时需重新关联。地图自身行列与单位用于独立布局；有来源时采用来源的尺寸与单位。

「生成地图原型」添加一组引用当前地图的场景，生成沿连接跳转的按钮，保留原有原型场景。新增按钮还绑定世界通路 ID 与正反方向；移动房间、调整移动限制、改变方向或文字条件后，预览实时检查最新设计。更改连接的目标地图或对象需要重新关联或生成，删除连接后不会继续沿失效通路跳转。按钮文案和场景编排仍可编辑；也可明确将按钮转为独立场景跳转。升级前已经生成的旧按钮保持原有独立动作，可重新生成以接入世界检查。

原型的「地图来源」也可手动选择，使用「编辑来源地图」返回。关闭地图模块后，已引用地图的原型仍能读取保存的数据。

示例的世界连接由既有玩法房间图初始化，后续在地图模块独立编排；已有玩法房间图保留。房间中的实体位置始终来自原玩法空间。地图不是第二套任务或故事状态系统，通行条件在第一版以设计说明保存，并由预演者确认。

## 存档与保护

地图存档键为 `gamecreator.workspace.v1:<projectId>:map-design`，结构版本 `schema: 1`。内容包括 `enabled`、`maps`、`connections`，以及兼容旧存档的可选 `world`（类型、世界单位、吸附步长）。各地图新增可选 `placement`；连接使用可选 `fromSide/toSide/travel`。物理通路新增地图 `openings/surfaces`、世界 `actor`、连接 `fromOpeningId/toOpeningId/structure`，以及返程落点、条件、限制和旧 ID 别名；字段均为兼容旧档的可选项。世界位置与局部对象位置分别存储，前端与桌面导入边界校验所有新增字段。

写入前校验格式并比较读取时的原始存档，检测另一个窗口的修改。写入失败保留草稿，阻止切项目、退出测试、登出和关闭窗口丢失编辑；可导出草稿、重试或重新读取。损坏的存档停止写入，不会自动重置为空白。地图／出入口仍被连接或原型引用时不能删除。上限为 100 张地图、500 条连接、每图 30 层和 300 个本地对象。

完整项目文件夹包含 `data/map-design.json`，关闭的模块也会迁移内容。旧文件夹缺少此文件时得到空白、未启用的模块。AI 文档仅导出已启用地图的区域、实际对象布局、关联和连接说明。模块暂限本地项目，与故事编排的共享范围相同。

## 示例与验证

`node scripts/build-map-examples.mjs` 更新空洞骑士、星露谷示例的 `mapDesign`，并在空洞骑士来源玩法中将 A 的底板拆成留有两个井口的地形；保留原对象身份和已有原型场景。空洞骑士包含 4 张地图、4 条物理双向通道，其中近岸竖井和远岸近路分别带实际梯子；星露谷包含农场、村庄和 1 条双向连接。`node scripts/sync-map-validator.mjs` 同步 Electron 文件夹边界使用的结构校验器。

模型与便携测试：`node --test tests/map-design.test.mjs tests/map-world.test.mjs tests/map-navigation.test.mjs`。客户端测试：`node tests/desktop-map-design.cjs` 、`node tests/desktop-map-world.cjs` 、`node tests/desktop-map-portals.cjs` 与 `node tests/desktop-map-physical.cjs`（可通过 `GAMECREATOR_PLAYWRIGHT_PATH` 指定 Playwright），使用隔离的临时项目和用户目录。
