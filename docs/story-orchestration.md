# 故事编排

故事编排用于文本驱动游戏的剧本创作：把章节、场景、对白、玩家选择、条件和后果组织为可阅读、可检查、可试玩的故事链。故事文档继续保存设定与说明，任务与流程继续描述玩家目标和阶段；故事编排通过任务引用与它们配合。

## 按项目添加

打开本地项目，在左侧 **工作区设置 → 可选模块 → 添加故事编排**。空白项目默认关闭；极乐迪斯科原型默认启用并填充故事，主导航直接显示“故事编排”。此次只有故事编排提供可选开关，其他模块沿用原来的入口。

关闭模块只隐藏入口，保留角色、正文、状态和所有分支；再次启用即可继续编辑。开关只影响当前项目，并随项目文件夹一起迁移。当前故事编排为本地项目功能，尚未接入团队同步。

## 从一段文字开始

1. 点击“新建故事”，填写名称。在“故事设置与关联任务”中指定入口、概要和关联任务。
2. 在“剧本编辑”添加场景，填写章节名称，建立对白、旁白、内心声音、调查入口或故事结果片段。
3. 为片段填写正文、说话人和玩家选项。每个选项可指定后继、开放条件、状态后果和时间成本，也可引用一个检定。
4. 在“角色与状态”定义人物和状态。证据、假说、关系、资源、技能可分别分类；状态使用数值，真假状态可设置为范围 0–1。
5. 打开“故事试玩”，从入口逐段阅读并选择。右侧显示模拟状态、任务进度及选择记录；可回退一步或重置。

条件支持组内全部满足、组间任意满足；不添加组表示无附加条件。后果支持赋值或增减。开启“后果只提交一次”后，已读内容可以回看，但不会重复发放证据、扣费或推进时间。低于状态下限会拒绝本次选择，超过上限会截断到上限；失败的选择不会留下部分状态更改。

“分支结构”按场景展示片段及跨场景后继，点击片段返回正文编辑。故事检查会指出失效引用、缺少后继、不可达片段及尚未填写的文字。未完成的草稿可以保存；存在引用的片段需先调整引用再删除。

## 检定、插话与结果

检定使用“2d6＋技能＋条件修正”与难度比较，双 1 失败、双 6 成功。试玩可输入骰点，或指定成功／失败来验证两侧内容。重试模式包括失败后可重试、仅一次、新来源解锁；多个选项引用同一个检定时共享结果，已成功或仅一次的检定只回看原结果。

自动插话按条件展示内心声音，不提交资源、时间或检定后果。需要改变状态时，在后续玩家选项中表达。中断按列表优先级判断，可用于资源归零、限时事件；“返回中断前内容”片段恢复先前阅读位置。自动跳转有步数上限，错误循环会显示提示。

叙事结果与任务进度分别填写。例如“误判结案”可以是任务完成，“暂缓调查”可以是任务暂缓；普通片段也可标记某项支线完成。故事和任务提供双向跳转。试玩中的任务进度、检定结果和状态只存在于本次模拟，不写回设计存档，也不作为游戏玩家存档。

## 港区疑案示例

新版极乐迪斯科原型默认启用故事编排：6 个编排场景、37 个片段、76 个选项和 5 个检定。正文约 5500 字，包含旅馆开场、现场取证、人物对话、内心声音、红白检定、住宿与家书支线，以及三种案件结果；片段使用独立标题。新建该原型项目后直接进入“故事编排”即可阅读和试玩，也可在工作区设置中关闭。

已经创建的港区项目不会自动被新版示例覆盖。旧项目启用模块后，在故事库展开 **从现有对白配置导入 → 导入港区疑案对白**，即可将当前项目配置转换为独立故事副本。此入口保留配置中的原始正文，不套用新版扩写稿。原配置表保留，后续在故事编排中维护，两者不自动互相同步。此入口针对港区疑案表结构；其他项目可直接新建故事。

可先指定检定成功，沿“进入调查 → 检查断绳 → 取得账册 → 取得证词 → 案情汇报”阅读真相路线；失败分支也保留搭档协助、维修便条和夜间复写件等替代路线。调查入口支持等待、按日程拜访人物和返回汇报。内心声音的假说不会自动成为证据。

当前试玩执行编排中定义的条件、后果、检定和时间规则。思想研究计时、完整装备系统、动画与游戏引擎运行时尚未接入；相关状态可在试玩初始状态中设置以检查路线。

## 保存与迁移

编辑自动保存到当前项目的 `story-orchestration` 存档。保存失败时保留当前草稿，并暂时阻止切换项目、退出登录或导出；可重试保存，或先导出草稿再重新读取。其他窗口已写入新版本时，不会静默覆盖。损坏或未知版本的存档停止写入。

项目文件夹导出始终保留模块开关和故事内容，包括关闭的模块。旧项目包缺少该部分时按“关闭且无故事”读取。AI 文档在模块启用时包含完整正文、角色、状态、选项、检定、后果与检查提示；关闭时省略故事编排章节。

验证命令：

```powershell
npm run build
node --test tests/story-orchestration.test.mjs tests/story-orchestration-portability.test.mjs
node scripts/validate-prototype-examples.mjs
node tests/desktop-story-orchestration.cjs
```

桌面验收需要 Playwright，可用 `GAMECREATOR_PLAYWRIGHT_PATH` 指定其安装目录。测试使用独立临时项目和用户配置，覆盖开关与隔离、旧项目导入、从零创作、三种结果、完整真相路线、失败与冲突恢复、重启和窄窗口。
