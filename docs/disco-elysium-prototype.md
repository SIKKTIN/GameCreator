# 极乐迪斯科 · 港区疑案原型

第四套内置示例用于检查叙事侦探玩法能否通过 GameCreator 的模块完整表达。案件、人物、台词、数值和美术规格是本原型的原创设计约定。它包含 5 个场景、6 名人物、1 条主线、2 条支线、两天日程和 3 种阶段结果。

## 打开与内容

在项目列表选择“从原型示例创建项目 → 极乐迪斯科”，填写名字即可创建独立本地项目。内容包括 8 张分层玩法核心图、8 份玩法设计、9 个程序系统/21 项功能、15 张配置表/198 条记录、5 篇故事说明、22 项美术需求/40 项资产台账。

玩法核心从主界面进入调查循环，再展开探索取证、对话与内心声音、红白检定、思想成长和日程，最后进入案情汇报。玩法和程序功能通过稳定 ID 关联；具体条件、状态和配置可从来源跳转。

全部玩法为草稿、原型试玩记录未测试、功能待开发、美术待制作。资产没有交付文件和采用版本。可在“工作区设置”添加可选的[故事编排](story-orchestration.md)，逐段阅读港区案件，模拟对白选择、状态后果与检定；这不代表游戏工程、思想研究计时等系统已经实现。

新版示例默认添加故事编排：6 个编排场景（含调查行动入口）、37 个片段、76 个选项、5 个检定，正文约 5500 字。扩写稿包含调查主线、住宿与家书支线、成败反馈和内心对白，在故事编排中独立维护。旧项目可启用模块后使用“从现有对白配置导入”，生成保留原配置正文的故事副本。故事结果区分查明真相、误判结案与暂缓调查；误判仍可完成任务，暂缓对应任务暂缓。

## 关键约定

- 客观证据、玩家假说、关系与思想状态分别记录。内心声音不能自动授予证据。
- 白检定失败需要新增的指定来源解锁；红检定无论成败只结算一次。多个对白入口共用同一检定 ID，选项的可重复性由检定状态管理。
- 断绳检查失败可付出额外时间请搭档协助；工头红检定失败会损伤关系，但留下维修便条；档案员缺席时夜间医师提供复写件。随机失败不会独自封死主线。
- 真相报告要求“绳端 AND（账册 OR 复写件）AND（证词 OR 便条）”，展开为四条 AND 规则。多组同时满足时界面只展示一个同义候选。
- 对话普通后继使用选项 target；有 check 时使用检定的 successNode/failureNode。完整解释契约保存在示例内的“运行规则与数据解释契约”。
- 时间按第一天00:00起的累计游戏秒保存，初始28800，截止165600。行动推进、思想进度和日程使用同一事务时间；移动、现实等待和读旧内容不计时。时间轴以每天86400秒分片，第二天加86400偏移。
- 住宿解决后，第一天21:00–24:00可休息至第二天08:00；第二天不能睡入第三天。截止后只保留案情汇报。

## 验证与迁移

`node scripts/validate-prototype-examples.mjs` 检查五套示例的模型和跨模块引用。`node --test tests/disco-prototype.test.mjs tests/story-orchestration.test.mjs` 检查附加数据引用、对话可达性、证据组合、成功/失败替代路线、白检定重试入口和两天日程。`node tests/desktop-story-orchestration.cjs` 验证故事编辑器内的完整阅读与选择路线，不代表已经完成游戏工程的实机试玩。

构建后执行 `node tests/desktop-prototype-import.cjs` 与 `node tests/desktop-gameplay-core.cjs` 检查客户端创建、模块显示、核心导航、编辑、重启与隔离。项目文件夹可通过正常导出保存到 `ProjectCache/极乐迪斯科/`，复制整个文件夹即可迁移；本机导出目录被 Git 忽略，源码中的内置示例随 master 分发。
