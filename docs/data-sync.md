# 数据同步

入口位于“数据与同步”分组，分为“导入”和“导出”。此模块只处理配置 JSON；文档、素材和开发反馈在“工程同步”中处理。

## 配置路径与第一次使用

1. 在“项目管理 → 工程连接”中保存游戏工程根目录。
2. 打开数据同步，填写相对路径，例如 `data/generated`。Godot 的 `res://data/generated/` 会规范为同一个路径。文件格式选择 JSON，保存同步设置。
3. 点击“读取并预览差异”。读取当前目录的 JSON 文件，不递归扫描子目录。
4. 文件名自动对应表名：`pvz_plants.json` 对应 `pvz_plants`；重读时自动匹配同名表。已导入配置在目录中也显示这个名称。
5. 先检查「字段对齐」：按字段 key（含已配置映射）对应，只在一侧存在的字段按整列汇总，显示存在/缺失，不逐条展示值。新增或缺失的记录按 ID 整条处理。
6. 在「值差异」表格中，上下两行分别显示 GameCreator 和引擎文件；只列出同名字段中有变化的记录与列。可批量采用一侧、按记录选择，或点击高亮单元格查看详情并填写自定义 JSON。删除仍需确认，批量采用不会自动确认删除。表信息与记录顺序单独列出。
7. 点击“应用导入”或“应用导出”。映射、JSON 类型及同步基准会保存在项目中，下次继续使用。

自动导出默认关闭。开启后，保存配置会在短暂防抖后导出**已有绑定、本地新修改、引擎未修改、无冲突、无删除**的文件。新文件绑定、引擎变更、冲突和删除仍需到数据同步手动处理。自动导出不自动导入。

## JSON 结构

| 文件内容 | GameCreator 编辑界面 | 再导出 |
| --- | --- | --- |
| `[{"id":"a","hp":100}]` | 记录表 | 保留根数组 |
| `{"schema_version":1,"rows":[{"id":"a","hp":100}]}` | 记录表 | 保留 rows 外的元信息 |
| `{"schema_version":1,"wave_counts":[3,5,8]}` | 对象配置：字段、类型、值 | 保留根对象，不额外插入 id 或 rows |

记录表的 `id` 必须是非空且唯一的字符串；`"001"` 不会变成数字 `1`。数字、布尔、空值、数组、嵌套对象、空字符串、缺失字段分别保留。对象配置可以展开数组或对象，编辑字段的 JSON 值，添加和删除字段。

已有表导入时保留同名字段的枚举/引用定义。引擎枚举值与已发布成员键双向转换；不存在的枚举成员、失效引用阻止导出。新建的本地表默认输出字符串，可在“字段定义”的“JSON 类型”中指定数字、布尔等类型。导入表未显式指定类型时沿用原文件类型。

JSON 中重复字段、重复 ID、无字符串 ID 的记录、非有限数字、不安全的大整数及危险键名会报错，不会静默截断或覆盖。大整数应使用字符串。当前限制单文件 8 MB、一次 200 个文件及 32 MB 输入总量，嵌套最多 64 层。

## manifest.json

引擎的 `data/generated/manifest.json` 是普通对象配置，表名为 `manifest`。例如：

| 字段 | 类型 | 值 |
| --- | --- | --- |
| schema_version | number | 1 |
| project_version | string | "0.1.0" |
| source | string | "docs/gamecreator/modules/data-engine/data.md" |
| wave_counts | array | [3,5,8] |
| spawn_count | number | 16 |

这些字段的业务含义由游戏项目定义。GameCreator 不会猜测并自动重算 `spawn_count`、`source_sha256` 等派生值。该文件与 GameCreator 自己保存在 `.gamecreator-sync/` 的同步归属、备份及事务记录互不混用。

## 当前植物大战僵尸工程的旧字段兼容

这个工程的现有设计表和生成文件有以下字段名差异。第一次同步时，在对应文件卡片展开“字段映射”，用下拉框选择右侧文件字段，再重新预览；成功同步后只需配置一次。

| 表 | GameCreator 字段 | 文件字段 |
| --- | --- | --- |
| pvz_waves | gap_s | interval_s |
| pvz_level | cols | columns |
| pvz_level | sky_first_s | first_sun_s |
| pvz_level | sky_interval_s | sun_interval_s |
| pvz_level | bullet_speed | projectile_speed |

核心同步模型不硬编码游戏字段。其他项目可以建立自己的映射。不要在未检查这些差异时把两个不同名称当作两个新字段直接合并。

旧工程的 `scripts/tools/export_design_data.py` 从设计 Markdown 重新生成这批 JSON；它与直接编辑 JSON 是两个写入来源。数据同步不会调用这个脚本。如果仍运行脚本，需要先确保 Markdown 与配置一致，否则脚本可能覆盖刚导出的数值，其 `--check` 也会报告不一致。`source_sha256` 在这个项目里指设计 Markdown 的摘要，不是四张 JSON 表的摘要。波次、格子大小等玩法校验继续由游戏侧负责。

## 差异与恢复

同步分别保存本地和引擎的上次状态。导入合并引擎变化，同时保留本地独立修改；同字段双方修改需要选择。导出不会静默覆盖引擎的独立修改。数组作为整体值比较，嵌套对象按字段比较，记录用 ID 匹配；记录顺序也会比较。

预览最多有效十分钟。应用前重新检查当前项目、保存的引擎连接、配置存档、文件内容及工程归属；任一变化都需要重新预览。丢失的文件不会自动删除本地表，取消同步或不勾选不会删除文件。数据目录不能与文档、素材、开发协作目录重叠，不允许越出工程或通过符号链接、硬链接写入其他位置。

同步前备份始终开启。工程文件原始字节和配置存档保存在 `.gamecreator-sync/data-history/<编号>/`，事务日志在 `.gamecreator-sync/data-pending.json`。一次同步出错时恢复已写入文件；进程异常退出后可使用“恢复中断同步”。

“恢复上次同步前”只在配置存档和工程文件仍符合该次同步结果时执行。如果同步后又有人修改，停止恢复并保留备份，避免覆盖新内容。首次数据同步也会建立与文档/素材同步共享的工程归属；更换项目必须先在工程同步中核对归属。

项目另存为和重新打开保留 JSON 类型、映射与历史。同步基准绑定项目身份、引擎、工程根目录和数据目录；更换连接或项目身份后不沿用自动写入许可。团队共享工作区暂未接入此模块。

## 实现与验证

- `shared/data-sync.mjs`：严格 JSON 解析、格式与类型往返、字段映射、三方比较。
- `desktop/data-sync.cjs`：复用工程路径检查/锁、预览令牌、事务与恢复、存档更新。
- `src/DataSyncPanel.tsx`：导入导出审阅与自动导出；`src/JsonObjectEditor.tsx`：对象配置编辑。
- `npm run test:data-sync`：模型与文件系统回归。
- `node tests/desktop-data-sync.cjs`：隔离 Electron 项目的导入、编辑、冲突解决、导出、自动导出及重启验收。通过 `GAMECREATOR_PLAYWRIGHT_PATH` 指定 Playwright 安装位置。

## 配置数据管理与同步规范

通用规范可在“程序框架 → 开发规范”阅读。生成 AI 文档时附带 `模块/config-data-policy.md`，完整总文档同时包含正文；引擎文档同步时附带 `<文档目录>/modules/data-engine/config-data-policy.md`。文档包含当前项目保存的数据目录、格式与适用范围，无需采用 Package/Core。目录或格式更改后重新生成并预览同步；文档只记录约定，不自动移动文件或修改游戏加载代码。


## 开发与稳定版本

配置编辑默认进入开发版，稳定版标签可只读浏览当前和历史快照，恢复只写入开发版并清空旧同步基准。`VersionStore.dataReleases` 可选；旧存档无此字段时全部视为开发版，首次手工发布后才建立稳定版本。快照随项目文件夹保存和项目包传输。

数据同步入口为：从引擎导入 / 开发字段说明 / 同步配置 / 发布稳定版。结构修改走导入和开发字段说明；手工及自动同步在桌面主进程中强制检查结构，冲突选择后的最终数据再次校验，禁止通过自定义 JSON 绕过结构检查。所有表均通过且与引擎无数据差异，方可确认运行验证并发布。发布预览过期、工程变更、文件变更或项目修订变化都会阻止发布。

字段说明写入配置目录 `_gamecreator/development-schema.json`；覆盖前备份到 `.gamecreator-sync/schema-history`，不覆盖实际引擎结构声明。引擎声明使用 `_gamecreator/engine-schema.json`，具体格式见内置《配置数据管理与同步规范》第 8 节。主目录扫描不递归，两个文件均不作为配置表。已有明确字段采用结构推断；缺乏证据的空值与复杂结构需声明。普通 JSON 未声明枚举及引用元数据时，不据此判为字段不符；仅比较引擎明确声明的 constraints。实际值仍需通过本地枚举及引用有效性校验。
