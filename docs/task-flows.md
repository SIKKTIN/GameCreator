# 任务与流程

任务与流程用于组织玩家目标、达成条件、阶段分支和完成结果。它引用玩法、程序功能、故事、美术资产与配置记录，支持委托、探索、关卡和挑战等内容。

## 创建与编辑

在本地项目左侧选择“任务与流程”，点击“新建任务”，只需填写名称。旧项目没有任务存档时显示空目录，只查看不会写入存档。

- **任务设置**：填写类型、说明、设计状态与进度范围（单次、每局、每日、跨局）。设计状态为草稿或已确认，由用户维护。
- **开放与后续解锁**：选择前置任务成功完成的全部／任一条件，以及额外的开放条件。反向显示以本任务为前置的后续目标。
- **关联内容**：引用玩法、程序功能、故事、美术资产、整张配置表或具体记录；点击可打开来源模块。配置记录入口打开所属表。改名时显示最新名称，删除或归档来源后保留引用并提示修复。
- **阶段与分支**：添加目标阶段、成功结果和失败结果，指定起始阶段。每个目标有名称、正整数数量和达成条件；阶段支持全部／任一目标。阶段顺序由分支连接决定。
- **结果**：记录奖励、标志、解锁或失败处理。成功结果表示满足后续任务的成功前置；失败结果不满足。结果节点为终点，重试路径应在目标阶段间连接。

分支在当前目标满足后可进入。对存在超时、阵亡等失败路径的目标，可以用“挑战结束”作为中立目标，或以任一目标表达“备齐物品／期限结束”，再按结果分流。普通战斗、计时、刷怪与暂停规则由关联玩法、状态流程和时间轴管理。

复制任务重新生成内部标识并重新映射阶段分支，外部内容引用和前置条件保留；副本为未归档的草稿。归档后设计只读，保留全部关系，可恢复。删除阶段前必须解除它的相关分支和起点设置；任务采用归档保留记录。

## 流程与预览

流程图按起点和分支自动排列，支持滚动和点击节点编辑，图下列出完整分支条件。

手动路径预览先确认假定开放条件满足，再填写当前阶段各目标的模拟进度。数量可以回退，例如背包物品被消耗后不再满足交付要求。满足全部／任一目标后，选择分支；有条件的分支须额外勾选本次预览假定满足该条件。

返回上一步恢复当时的模拟计数；进入阶段时计数重新开始，包括循环回到同一阶段。成功或失败结果显示设计中的结果文本。重置、切换任务、切换编辑视图或修改设计会清除预览。预览不写入任务存档，不改变设计状态，不自动解释条件、执行游戏、扣物品或发奖励；计时单位与事件口径在达成条件中说明。

设计检查报告失效引用、前置关系无法解锁、起点缺失、不可达阶段、无法到达结果的回路、缺少目标和多分支缺少条件。允许保存未完成设计；检查通过只表示结构完整，不表示逻辑条件必定可满足或已完成实机验证。

## 五个原型

| 原型 | 内置目标 |
| --- | --- |
| 空洞骑士 | 永久冲刺、裂隙近路、首领与唯一奖励（3个） |
| 星露谷物语 | 三颗萝卜委托、七日生活（2个） |
| 植物大战僵尸 | 三波草坪关卡的胜负结果（1个） |
| 极乐迪斯科 | 港区疑案与三种报告结果、住宿、家书（3个） |
| 吸血鬼幸存者 | 生存挑战、两个角色解锁、累计击杀武器解锁（4个） |

这些是原型已有规则的设计表达，全部保持草稿。更新内置示例后，需要“从原型示例创建项目”建立新副本才能看到新增内容；已有本地项目不被覆盖。

## 保存、迁移与协作范围

存档键为 `gamecreator.workspace.v1:<项目标识>:task-flows`，schema 1。设计按项目及测试工作区隔离保存，模拟进度不持久化。

沿用磁盘原子写入与备份，读到损坏存档停止写入。保存失败或发现其他窗口更新时保留当前草稿，可重试、导出 JSON 草稿备份，或确认丢弃未保存草稿后重新读取存档。未保存时保护项目切换、测试工作区切换、退出登录、关闭窗口和 AI 导出。

AI 文档包含任务、阶段、目标、分支、引用和待完善项。项目文件夹导出包含 `data/task-flows.json`，导入时按新项目身份隔离；旧文件夹缺少此模块时补充空任务。旧版客户端尚不识别包含该模块的新项目包，应使用支持此模块的版本导入。

本阶段接入本地项目。团队项目的该入口仍标记未接入；发布本地项目到协作服务器不会同步任务数据。
