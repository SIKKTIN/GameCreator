# 项目打开与保存

GameCreator 是编辑工具。项目内容保存在独立文件夹中，可以与软件分开搬迁、备份与管理版本。

## 日常操作

- **新建项目**：填写名称，再选择保存位置。保存对话框中的名称用于创建新的项目文件夹，不要求先连接引擎。
- **从原型示例创建项目**：选择示例和名称，再选择保存位置；所有示例内容直接写入新文件夹。
- **打开项目**：选择包含 `project.gamecreator` 的文件夹，直接读写该目录；重新打开同一项目不会生成新身份。
- **保存项目 / Ctrl+S**：检查当前项目存档。编辑时已自动写回原目录，每个模块保留上一份 `.bak` 备份。
- **项目另存为**：选择新文件夹，复制全部模块、素材历史版本和原文件并切换到副本。副本使用新身份，清空引擎连接并关闭自动同步，之后在工程连接重新连接。
- **右键 → 打开项目文件夹**：打开该项目数据所在目录，而不是游戏引擎工程。
- **右键 → 移除项目**：仅移除最近项目记录，磁盘内容保留，可以再次打开。

已保存的 GameCreator 项目目录与“工程连接”里的 Godot / 绿洲启元目录是两个独立位置。同步仍写入连接的游戏工程，不改变项目的保存位置。

## 文件夹结构

```text
我的项目/
├─ project.gamecreator       # 版本、固定项目身份、名称、引擎连接设置
├─ README.md
├─ archives/                 # 各模块 JSON 存档，包含真实存档 key 与 value
│  ├─ <存档键的 SHA-256>.json
│  └─ <存档键的 SHA-256>.json.bak
└─ assets/                   # 素材所有版本的原始文件
```

打开期间会生成 `.gamecreator-lock`，防止两个客户端同时覆盖同一项目。关闭客户端后释放；异常退出的锁在进程已结束后可自动恢复。搬迁前先关闭项目所在客户端，再复制整个文件夹，不要遗漏 `archives` 或 `assets`。另一台机器直接“打开项目”，不需要原机器的软件缓存。引擎工程本身不会一并复制，应按新机器路径重新连接。

目录失效、入口身份不符或存档损坏时停止读写，不会自动退回内部缓存或在旧路径创建一个空项目。

## 旧项目迁移

旧内部存档仍可读取。首次点击“保存到文件夹”时选择新目录，保存完整内容和素材版本，再将最近项目指向新目录。保留原项目身份与已连接的引擎工程，软件原来的内部存档不删除。

以前导出的 `manifest.json` 文件夹也可通过“打开项目”打开。先校验旧清单和文件哈希，再在原目录创建新版入口及 `archives`。旧 `manifest.json` 和 `data` 保留作为迁移前备份，后续编辑以新版入口及 `archives` 为准。

## 包含的内容

- 项目概览、里程碑与故事文档。
- 项目排期的制作任务、计划与实际日期、负责人、前置依赖、内容来源与验收记录；旧包缺少排期时从包内里程碑恢复，详见[项目排期](project-schedule.md)。
- 玩法设计，以及依赖、条件规则、状态流程、空间布局和时间轴。
- 玩法核心、原型场景与交互、任务与阶段流程。
- 故事编排的启用状态、正文、条件、检定与后果；关闭的模块也保留内容，旧包缺少此部分时默认为关闭。
- 功能系统、能力、依赖和配置引用。
- 配置表定义与记录、枚举稳定版、候选版、审核及发布历史。
- 素材需求、资产台账、全部交付版本、审核与采用关系，以及每版的实际原始文件。
- 已保存的数据配置视图偏好。


所有设计中的内部引用和审核历史保留。正式本地项目使用此流程；团队项目继续按团队服务器的协作机制保存，测试工作区保持隔离。浏览器开发模式不提供本地文件夹接口。

## 兼容归档脚本

`ProjectCache/` 是 Git 忽略的本机项目目录。旧版五套示例快照仍可打开；新版独立项目在原目录持续保存。

旧归档脚本继续提供只读便携快照，支持最近列表中的独立项目。先关闭使用该项目的客户端，避免写入锁冲突：

```powershell
node scripts/export-project-folder.mjs --project "完整项目名或 ID" --output "ProjectCache/新的归档目录"
node scripts/verify-project-folder.mjs "ProjectCache/新的归档目录"
```

这些脚本仍生成或校验旧 `manifest.json` 快照格式，不能替代编辑器的日常打开与保存。
