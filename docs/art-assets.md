# 素材资产

素材模块用于提供制作文档、记录工程内交付位置并跟踪美术任务。素材原文件直接生成和维护在游戏工程内，不再要求在 GameCreator 中导入图片、审核交付版本或采用版本才能完成。

分类与统一条目保留，包括角色、场景、动画、UI、音频及自定义分类。详情分为“制作要求”“工程交付与进度”“使用位置”，制作方案仍有独立入口。新建条目只需要名称。

## 美术风格

模块页签为“美术风格 / 素材条目 / 制作方案”。风格遵循“项目基准 → 分类补充 → 单项特殊要求”的顺序：

- 项目基准描述整体方向、氛围、视角与比例、表现方式、轮廓、光照、材质、界面、动画和应避免的表现。色板包含可视化色块、颜色名称、色值与用途；参考记录来源或工程路径、采用特点与反例。
- 分类补充沿用现有分类的稳定 ID，支持角色、场景、UI 及自定义分类。改名保留关联；删除分类保留历史说明，原条目转入未分类后需要重新核对。音频等非视觉分类可注明视觉规则不适用。
- 素材“制作要求”展示当前生效基准与所属分类规则。特殊要求需要记录原因，才能标记“风格已复核”。此复核只记录标准核对，不代表完成制作或通过验收。

编辑先保存为草稿，填写整体方向与确认说明后，点击“确认美术风格基准”生成不可覆盖的版本。未填写的字段保持“待确定”；旧项目不会自动获得像素、卡通或写实等预设。参考第一版支持文本、网址和路径说明，不导入或复制原图。

确认新版本后，只把受影响素材提示为“待风格复核”。仅修改场景补充时，角色不会失去复核状态；调整全局要求、素材分类或单项特殊要求时，相关条目需重新核对。未确认草稿不改变生效标准。制作完成状态、排期和既有验收结果始终保留。

生成提示词复制时附带当前适用风格，手写提示词不被覆盖。制作方案按关联素材展示适用要求；AI 总文档、素材模块 Markdown 和引擎同步文档均包含风格基准、分类规则、单项例外与复核提示。草稿单独注明为未确认，不能作为当前制作标准。未保存修改会阻止导出与同步。

存档沿用素材 schema 1，可选 `style` 保存 `draft` 和不可覆盖的 `versions`；条目的 `styleException`、`styleReview` 分别保存特殊要求与复核快照。项目内容反馈可提出已有草稿字段的修改，但不能改写已确认版本或伪造复核记录。独立项目保存、导入、备份均保留这些字段。

## 制作与交付

- 制作要求：说明、规格、验收标准、负责人、日期、优先级与生成提示词。
- 工程交付与进度：相对于引擎工程的交付路径、交付与验证说明、关联美术任务的状态和开发结果。支持关联已有美术任务、新建美术任务、跳转排期查看，以及解除直接任务关联。
- 使用位置：玩法、功能、其他模块的引用与共用资源关系。引用使用稳定 ID，改名不影响关联。可在“管理共用资源关联”维护旧资源复用，不需要复制文件。

没有关联任务的条目可手动设置制作状态；已有关联美术任务时，由任务进度管理状态，避免两个页面各自维护。工程路径和反馈结果仅作为文档展示，不会执行路径、命令或链接。

## 排期与反馈联动

只使用明确引用此素材需求或其关联资源的 **美术** 任务；程序接入、测试任务与名称相似的任务不会自动关联。资源被多份需求共用时，资源进度汇总所有使用需求的美术任务；某份需求不会因为另一个需求引用了同一资源而继承对方的独立任务。

| 关联美术任务状态 | 素材显示 |
| --- | --- |
| 全部已完成 | 已完成 |
| 任一受阻 | 需修改 |
| 全部待验收或已完成，尚有待验收项 | 待验收 |
| 有任务开始，未满足以上条件 | 制作中 |
| 全部待开始 | 待制作 |

存档沿用 schema 1，“已完成 / 待验收”内部仍保存为“已通过 / 待审核”。不要求图片文件或采用版本。归档条目保持原状态，恢复后重新同步。解除全部关联后转为手动管理，保留最后一次状态。

开发者读取工程内 `gamecreator/context/tasks.json` 及素材文档，在工程中完成美术后，通过任务反馈的 `status`、`result` 提交状态、交付路径、验证结果与未完成项。GameCreator 应用反馈并核实验收后，关联素材随排期刷新。“已完成”仍需要用户确认，不会因为读取反馈文件就自动接受。

已存在的项目在打开时按当前排期补齐素材状态。只有已保存的排期才能驱动同步；排期保存失败时不提前完成素材，素材同步保存失败时显示错误并提供“重试保存素材资产”。

## 旧项目与文件兼容

原需求、资源、分类、稳定 ID 和关联保持兼容。旧图片与版本元数据保留在“历史导入文件（只读）”中，主流程不再提供图片导入、采用和审核入口。原文件仍随项目备份保存，不会自动删除。

已关联并属于同一分类的需求与资源显示为一张卡片；其他分类的独立资源保留入口。旧独立资源可编辑名称、说明、工程交付说明与状态，也可补充制作要求；转换保留完成状态与交付文档。移动分类时独占资源随条目移动，共用资源保留原分类。

引擎同步的新配置默认输出文档和开发协作上下文，不再默认复制素材版本。旧项目已保存的同步范围继续保留；“同步历史已采用素材”仅用于旧文件兼容，可关闭，工程内已经交付的文件会保留。制作方案中的参考图继续作为文档附件，不参与完成判断。

## 卡片删除

在素材目录或分类首页搜索结果中，右键卡片选择“删除素材条目”，确认后删除。键盘聚焦卡片后可用 Shift+F10 或菜单键打开菜单；Escape 关闭菜单或取消确认。右键操作始终针对该卡片，不会误删右侧正在编辑的其他条目。

删除统一条目会在一次存档写入中移除该条目的制作要求、关联以及独占资源的版本记录。其他条目共享的资源保留，已导入的本地文件也继续保留。分类映射和当前选中详情同步更新；归档条目也支持明确确认后删除。普通编辑仍不允许修改、删除已有版本内容。

删除前同时检查制作要求和将要删除的独占资源。被制作方案、原型、地图、任务、故事角色头像、故事文档或项目排期引用时，确认窗口列出引用位置并停止整个删除操作。检查包含已归档内容及已关闭模块，避免恢复后引用失效。

删除单独写入已提交的存档，成功后才更新界面；失败时卡片保留，可在窗口中重试。有未保存修改或关联存档不可读时暂不可删除，其他窗口已修改存档时要求重新打开项目。

## 保存与导出

元数据位于 `gamecreator.workspace.v1:<项目标识>:art-assets`。可选字段 `delivery` 记录 `path` 与 `notes`；资源的 `productionStatus` 保存制作状态；`scheduleProgress.taskIds` 记录状态来源。旧项目缺少这些字段时正常读取。

保存失败保留草稿并可重试；未保存时保护项目切换和文档导出。损坏存档、其他窗口更新不会被直接覆盖。项目与测试工作区相互隔离。

AI 文档和引擎同步文档输出制作规格、验收标准、生成提示词、制作状态、交付路径、验证说明与关联任务 ID。旧文件记录单独注明为历史，不作为当前制作要求。独立项目备份应在关闭项目后复制整个目录，保留 `archives/` 与历史 `assets/`。

## 验证

- 构建：`npm run build`。
- 风格：`node --test tests/art-style.test.mjs`；界面与文档闭环：`node tests/desktop-art-style.cjs`。
- 模型：`node --test tests/material-progress.test.mjs tests/material-items.test.mjs tests/art-assets.test.mjs tests/art-deletion.test.mjs tests/art-library.test.mjs`。
- 文档与进度界面：`node tests/desktop-material-progress.cjs`。旧的 `desktop-material-items.cjs`、`desktop-art-assets.cjs` 入口转调这份验收。
- 反馈闭环：`node tests/desktop-engine-feedback.cjs`，包括应用美术任务反馈后自动刷新素材进度与结果。
- 分类、删除、独立文件夹：`desktop-art-library.cjs`、`desktop-art-deletion.cjs`、`desktop-folder-projects.cjs`。

桌面测试通过 `GAMECREATOR_PLAYWRIGHT_PATH` 指定 Playwright，使用隔离存档和临时工程，不覆盖用户项目。
