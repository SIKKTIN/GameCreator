# 素材资产

素材资产默认统一显示“素材条目”。分类继续保留，进入角色、场景、动画、UI、音频或自定义分类后，直接选择素材卡片。卡片显示制作状态、负责人、日期、交付文件数与版本数，不再切换“制作需求 / 资产文件”两个目录。

新建条目只填写名称，自动属于当前分类。详情内有三个页签：制作要求、交付与版本、使用位置。制作方案仍保留独立入口。

## 制作要求与分类

“制作要求”维护说明、规格、验收标准、负责人、优先级、日期、进度和生成提示词。“所属分类”使用项目原有目录，支持新增、改名、排序和删除自定义分类；删除分类将内容移入未分类，不删除素材。制作类型和目录分类继续分别保留旧数据。

“使用位置”可关联整份玩法、条件规则、状态、时间事件、空间对象及程序功能，并显示资源复用和其他模块的引用位置。关联按稳定 ID 保存；改名后显示最新名称，来源失效会提示并保留记录供修复。原有玩法、功能、全局搜索和交付链接仍可打开对应条目。

一个条目可包含多个交付资源，例如独立审核的角色造型和攻击动画；一个交付版本可以包含多个文件，通常不用为每个文件新建条目。在“交付与版本 → 复用已有资源 / 拆分交付”中可关联已有资源或创建独立交付，同一资源不会因被多个条目使用而复制。

## 旧项目兼容

统一条目是原需求、资源及其关联的视图，打开旧项目不会改写内容、分类、版本或文件。已关联并属于同一分类的需求与资源只显示一张条目卡片。共享资源可在每个使用它的条目里查看；原本单独归在其他分类的资源保留该分类入口。

没有制作要求的旧资源仍显示为条目，可直接管理版本，也可点击“补充制作要求”增加负责人、进度和规格，已有资源与文件不复制。移动条目分类时，其独占交付资源随之移动；共享资源的分类保留。条目归档保留历史，且不会归档其他条目共用的资源。

## 交付版本与审核

在条目的“交付与版本”中点击“导入交付文件”，直接选择第一批文件，无需另建资产卡片再手动关联。后续点击“导入新版本”，可多选文件，填写版本名称、备注并指定是否属于占位。首次取消文件选择时只保留空交付资源，可稍后继续导入。文件和版本内容提交后保留为历史记录；替换素材应导入新版本。

每版单独记录待审核、需修改或已通过及审核反馈。占位版本可先采用；正式版本须审核通过才能采用。采用新版本不会删除旧版本，历史已通过版本可再次采用。

条目“已完成”（存档中仍为“已通过”）要求至少关联一项资源，且所有关联资源都采用了非占位、审核通过的版本，由用户明确确认完成。占位可用与正式交付完成分开显示。需要撤回正在采用的正式版本审核时，先调整关联条目的状态并取消采用，避免已完成条目静默失效。

已归档需求和资产只读，现有引用保留，恢复后可以继续编辑。首版不提供物理删除历史交付文件。文件复制成功后若取消版本提交，本地副本会保留为未关联文件；不会自动清理已有文件。

## 卡片删除

在素材目录或分类首页搜索结果中，右键卡片选择“删除素材条目”，确认后删除。键盘聚焦卡片后可用 Shift+F10 或菜单键打开菜单；Escape 关闭菜单或取消确认。右键操作始终针对该卡片，不会误删右侧正在编辑的其他条目。

删除统一条目会在一次存档写入中移除该条目的制作要求、关联以及独占资源的版本记录。其他条目共享的资源保留，已导入的本地文件也继续保留。分类映射和当前选中详情同步更新；归档条目也支持明确确认后删除。普通编辑仍不允许修改、删除已有版本内容。

删除前同时检查制作要求和将要删除的独占资源。被制作方案、原型、地图、任务、故事角色头像、故事文档或项目排期引用时，确认窗口列出引用位置并停止整个删除操作。检查包含已归档内容及已关闭模块，避免恢复后引用失效。

删除单独写入已提交的存档，成功后才更新界面；失败时卡片保留，可在窗口中重试。有未保存修改或关联存档不可读时暂不可删除，其他窗口已修改存档时要求重新打开项目。

## 文件与保存

元数据按项目存入 `gamecreator.workspace.v1:<项目标识>:art-assets`，schema 1。旧项目默认空目录，只查看不会写入空档案。项目之间以及正式/测试工作区之间独立保存。

桌面导入使用系统文件选择器，将文件复制到独立项目文件夹的 `assets/` 中；尚未迁移的旧内部项目保存在 `.gamecreator/art-files/` 下按项目隔离的目录中，不依赖导入来源继续存在。PNG、JPEG、WebP、GIF 可预览；其他格式保留交付文件，可在文件夹中定位。单文件最大 100 MiB，图片预览最大 12 MiB，且需满足有效图片结构、宽高各不超过 16384 和总像素不超过 4000 万。SVG/HTML 不作为内嵌页面执行。

独立项目备份时应关闭项目并复制整个项目文件夹，包括 `archives/` 和 `assets/`；旧内部项目可先“保存到文件夹”迁移，或备份整个 `.gamecreator/`。浏览器开发模式可以管理需求、版本元数据和关系；文件导入与本地预览需使用桌面软件。

保存失败保留当前草稿并提供重试；未保存时保护项目切换、测试工作区切换、退出登录、关闭窗口和 AI 导出。损坏存档停止写入，版本冲突不覆盖其他窗口数据。

AI 文档导出需求规格、来源、进度、关联资产、交付历史、审核反馈及当前采用版本。每份完整需求和资产只输出一次，玩法及功能章节使用引用。导出不打包图片或二进制交付文件。

## 验证

- 构建：`npm run build`
- 模型与文件存储：`node --test tests/material-items.test.mjs tests/art-assets.test.mjs tests/art-deletion.test.mjs tests/art-library.test.mjs tests/art-files.test.cjs`
- 统一条目验收：`node tests/desktop-material-items.cjs`，覆盖旧分类、首批文件导入、多文件版本、审核完成、复用、归档、删除、旧资源补充要求和重启。
- 桌面验收：`node tests/desktop-art-assets.cjs`，通过 `GAMECREATOR_PLAYWRIGHT_PATH` 指定 Playwright 模块路径。使用隔离存档，不覆盖真实项目。
- 卡片删除验收：`node tests/desktop-art-deletion.cjs`，覆盖右键与键盘、取消、引用保护、归档版本、本地文件保留、失败重试、跨窗口冲突、分类搜索结果及重启。
- 独立项目兼容：`node tests/desktop-folder-projects.cjs`，覆盖现行打开、保存和另存为，以及五个原型的素材条目读取。旧 `desktop-project-package.cjs` / `desktop-prototype-import.cjs` 仍依赖已退役的迁移入口或内部存档创建流程，不能替代此项验收。
