# 原型设计

原型设计把已有玩法空间和独立界面组合成可点击的画面。首版用于验证开始界面、关卡进入、房间游览、结果页和弹层显隐。点击出口完成房间切换；角色移动、攻击、跳跃、碰撞和条件表达式执行尚未实现。

## 编辑流程

1. 在本地项目打开「原型设计」。没有场景时显示起始页，可从空白场景开始，或在「从玩法空间生成」中选择已有空间并添加场景组；尚无玩法空间时可直接前往玩法设计。创建首个场景后显示场景目录、画布与属性栏，删除最后一个场景后返回起始页。
2. 场景组包含开始界面、对应空间或各个房间；房间连接生成初始跳转按钮，双向连接生成两个方向。入口是首个房间，可在开始按钮的动作目标中调整。
3. 加入文字、按钮、色块、图片、交互热点。左键拖动独立元素，滚轮缩放、右键平移；位置和尺寸也能在属性栏调整。后面的元素绘制在上层，可以前移、后移。
4. 选择空间对象可让元素跟随对象的位置、尺寸与旋转；对象布局仍在玩法设计中编辑。图片明确绑定美术资产、版本和文件，不随采用版本变化而替换。
5. 为元素指定点击动作：切换场景、显示、隐藏、切换显隐、重新开始。独立结果页可以用普通场景制作，再连接到完成按钮。
6. 设置启动场景，使用「从头预览」或「预览此场景」。预览在临时状态中执行；每次进入场景恢复初始显隐，退出后所有预览状态丢弃。

## 引用与范围

- 房间拓扑用于生成场景间的导航。预览显示房间内部布局，不把拓扑卡片的位置当成真实世界坐标。
- 空间对象和关联热点共用同一坐标变换，网格与自由布局使用现有空间几何。仅保留来源引用，不复制空间对象。
- 生成时的房间连接和文字条件用作可编辑的初始交互。后续变更原型跳转不会改写玩法空间连接，空间布局本身实时引用来源。
- 条件是预览者人工确认的通行要求；「本次满足」才会执行对应动作。原型不会自行解释任意设计说明或运行代码。
- 场景可关联玩法核心节点，便于在导出文档中追溯设计来源。
- 引用缺失保留为可修复的草稿，并列入检查。删除被其他场景跳转引用的场景、被显隐动作引用的元素会被阻止；空间对象仍被原型热点引用时也禁止删除。
- 本版供本地项目使用。团队项目沿用现有模块能力开关，原型设计显示为「未接入」，不会把本地编辑误报为团队同步。

## 保存和迁移

每项目使用 `gamecreator.workspace.v1:<projectId>:prototype-design`，存档版本为 `schema: 1`。不存在存档时显示空白状态，不自动写入。

拖动结束只提交一次。写入失败保留完整草稿，可继续修改或重试保存，并阻止切换项目、退出测试工作区和登出。读取损坏存档时停止写入；提供草稿备份和重新读取。多窗口写入采用原始内容比较，防止覆盖其他窗口的新版本。

项目文件夹包含可选文件 `data/prototype-design.json`，受清单哈希校验和导出快照检查保护；图片继续使用美术资产的原始文件迁移链路。旧文件夹没有该存档时正常导入为空白原型。内置示例允许可选字段 `prototypeDesign`，AI 文档包含场景、元素、动作与来源。

现有用户项目与 ProjectCache 不会因升级自动增加场景；通过「添加场景组」明确创建。删除过的项目不会恢复。

## 验证

- `tests/prototype-design.test.mjs`：五个原型的所有玩法空间生成、引用稳定性、预览显隐/条件、复制与删除保护、存档冲突、项目迁移。
- `tests/desktop-prototype-design.cjs`：植物大战僵尸开始/关卡切换、空洞骑士房间出口、条件确认、缩放后拖动、取消、保存失败重试、图片版本绑定、窄窗口、项目切换及重启。
- 项目文件夹与原型示例既有测试覆盖旧格式兼容、哈希验证和导出期间的并发修改。
