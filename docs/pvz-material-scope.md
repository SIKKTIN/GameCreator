# 植物大战僵尸 · 最小原型素材范围复核

本次按现有玩法、4 张配置表、17 个可点击原型场景和程序功能复核，范围仍为单人 PC 鼠标、一张白天草坪、5 行 × 9 列、3 种植物、2 种僵尸、3 波 11 条刷怪事件、共 16 只僵尸。素材规格是本工具的原型设计约定。

## 为什么角色目录之前只有一项

现有 20 条制作需求已包含五种单位。向日葵、豌豆射手和普通僵尸的制作类型是“动画”，旧目录沿用制作类型推导，导致这些整套单位需求出现在动画目录；路障僵尸被归到敌人与首领，角色目录只剩坚果墙。多个类别共用的资产又被推导成未分类，例如植物头像和阳光符号。

本次为 PVZ 明确保存目录映射：**角色目录包含三种植物的完整需求，敌人与首领包含两种僵尸的完整需求**。资产按实际交付类型归档，动画、图标、共用 UI 和反馈分别查找。五个单位的既有需求和动作不重复建立；新增五份独立定型与配色基准，保证动作、头像、覆盖层有明确的外观参考。

## 单位清单

| 单位 | 必需交付 | 可复用内容与边界 |
| --- | --- | --- |
| 向日葵 | 定型配色基准、待机与产出动作、卡牌头像 | 共用受击、生命条、移除反馈；阳光是独立资源 |
| 豌豆射手 | 定型配色基准、待机与发射动作、卡牌头像 | 朝右发射；豌豆与命中特效单独交付 |
| 坚果墙 | 定型配色基准、静态/轻待机与受压表现、卡牌头像 | 无攻击和产出动作；首版生命条足够，不强制裂纹分阶段 |
| 普通僵尸 | 定型配色基准、共用步行与啃咬序列 | 朝左、无根位移；命中与死亡使用共用反馈 |
| 路障僵尸 | 组合定型配色基准、路障识别覆盖层 | 复用普通僵尸身体和动作，只有一条生命条，不做护甲脱落、破甲动画或第二阶段 |

三种植物使用现有建议 96×96 透明画布，僵尸基底使用 96×128；保留可编辑源文件、统一锚点、帧序与事件说明。定型图与局内视角一致，原型不额外要求背面和三视图。第一次产出、发弹、有效啃咬由玩法事件控制，动画不能增加逻辑前摇、伤害或资源结算。

台账里的“资产”是待制作交付条目，并不表示已经存在图片文件。原有 32 项保留，新增上述 5 份定型图；20 条需求继续保留原 ID、来源及状态，共 55 条需求—资产关联。

| 资产目录 | 数量 | 本版内容 |
| --- | ---: | --- |
| 角色 | 3 | 向日葵、豌豆射手、坚果墙的定型与配色基准 |

| 特效 | 7 | 豌豆、单体命中、受击高亮、单位移除、阳光产生/收集、格子判定标记、种植落位 |
| UI | 10 | 生命条、卡牌框/冷却状态、阳光余额栏、波次预告、波次/生成/存活计数、共用面板与按钮、操作说明、暂停遮罩、胜利标记、失败/突破行标记 |

一项动画资产可包含多个动作片段；一项 UI 资产可包含默认、悬停、选中、禁用、冷却等状态。数量统计的是独立交付包，不是帧数或 PNG 文件数。共用文件不因被多个需求引用而重复制作。

## 状态覆盖与验收

- 空棋盘与左右边界：开局不烘焙任何植物、僵尸、阳光或 R3 示例防线。
- 三张种植卡：头像、成本文字位、冷却遮罩、选中和不足状态；数字由程序填入。
- 输入反馈：可种/不可种格、右键取消、铲子工具及移除；不能暗示拖拽种植或退款。
- 五种单位：可辨识外观、必要动作、共用受击/生命/移除；草坪、子弹与 HUD 不互相遮挡。
- 阳光：同一符号用于天降、植物产出、价格和余额栏；产生、点击确认和超时移除符合原规则，不增加自动拾取。
- 波次：提前提示、生成/存活计数、最后一波后的清理提示；预告不是生成延迟。
- Ready / Running / Paused / Won / Lost：操作指引、开始/继续/重开按钮、暂停层、胜负标记；终局只出现一次，重开清空上一局反馈。
- 项目配置、空间布局、原型场景、功能接口及数值不因本次素材复核改变。所有待制作条目仍无实际交付，不改变未测试状态。

## 本版不要求

夜晚、泳池、屋顶、额外植物/僵尸、Boss、割草机、局外商店、关卡选择、图鉴、成就、掉落奖励；角色专属死亡动画、完整三视图、独立僵尸第二套骨架、路障脱落也不作为本版必需交付。

声音尚未列入该最小原型的玩法与功能契约，当前验证可以静音完成。对外演示时可另立音频需求，先做点击/种植、拾取、发射/命中、啃咬、预警、胜负等短音效，再考虑一首循环音乐；不混进上述 37 项视觉交付，也不套用图片生成规格。

## 已有项目修订

模板已经包含此次清单。已有项目需显式运行 `scripts/apply-pvz-material-review.mjs <工作树根目录> <项目ID>`：只更新指定项目的素材存档，先在 `.gamecreator/backups/` 备份原值，再按原始值检查并写入。不会删除资产、覆盖交付版本、修改其他模块或重建项目；用户自定义分类、已归档条目和已通过需求受保护。重复执行不会重复添加资产、关联或补充说明。

客户端已打开时，切换到其他项目再切回即可读入新版；旧窗口若试图保存过期内容，会提示版本冲突。
